## 의도
엑셀에 의존해 한 사람이 여러 간호사의 근무 가능 일정과 규칙을 수작업으로 검토하면서 월간 근무표 작성에 오랜 시간이 걸리는 문제를 줄인다.

## 기대 결과
관리자가 규칙 기반으로 월간 근무표 초안을 자동 생성하고, 조건 충돌과 배치 불가 이유를 확인해 수정·확정·공개한다. 간호사는 공개된 근무표를 조회한다. 목표는 월간 편성 소요 시간을 기존 대비 절반 이하로 줄이는 것이다. 현재 엑셀 기준 시간은 모르므로 파일럿에서 기준선을 측정한다.

## 사용자와 권한
- 스케줄 관리자(수간호사 등): 간호사/근무 데이터 입력, 승인된 휴가 일정 등록, 규칙 설정, 수동 편성 및 자동 배치, 검토·수정·확정·공개.
- 간호사: 공개된 근무표 조회. 직접 편집 또는 신청 기능은 현재 범위에 포함된다고 확정되지 않았으며, 계획 단계에서 읽기 전용 가정으로 다룬다.

## MVP 범위
1. 월간 근무표 달력과 근무 유형(예: 데이/나이트/오프) 표시.
2. 간호사별 근무 가능 시간과 이미 승인된 휴가/반차를 등록·관리.
3. 관리자가 직접 간호사를 배치할 때 날짜·시간별 근무 가능 여부 및 불가 사유를 즉시 표시.
4. 설정된 hard rule을 지키는 자동 배치로 월간 초안을 생성.
5. 균등 배분 등 soft objective를 가능한 한 최적화하고, 달성되지 않은 항목과 이유를 표시.
6. 불가한 슬롯을 비워 두고 사유/관련 규칙을 표시. hard rule을 자동으로 완화하거나 위반하지 않는다.
7. 관리자가 자동 초안을 수정한 뒤 확정하면 해당 revision이 활성 달력에 공개 적용된다. 미충원 표도 부족 현황을 확인한 뒤 확정할 수 있다.
8. 간호사는 병동 전체 달력과 본인 일정만 보기 중 선택한다. 확정 전 초안은 보이지 않는다.

## 필수 규칙 및 최적화
### 반드시 지킬 조건 (hard constraints)
- 관리자가 등록한 지정 휴가 날짜에는 배치하지 않는다.
- 반차 등록 시간대와 겹치는 근무에는 배치하지 않는다. (오후 반차면 오후 근무 불가)
- 나이트 근무 다음날 데이 근무를 배치하지 않는다. 구체적 휴식시간 규칙은 계획 단계에서 설정 가능하도록 설계한다.
- 시스템은 위 조건을 자동으로 어기지 않는다. 가능 배치가 없으면 빈 슬롯과 사유를 노출한다.

### 가능한 한 맞출 조건 (soft objectives)
- 간호사 간 근무의 균등 배분을 가능한 한 개선한다.
- 최적화하지 못한 경우 어느 조건/인원 때문에 그런지 설명한다.
- 세부 점수식과 여러 공정성 정의는 병원/병동 정책에 따라 설정할 수 있도록 계획 단계에서 구체화한다.

## 비목표
- 급여, 근태, 출퇴근 기록 관리
- 휴가/반차 신청 및 결재 워크플로
- 법정 연차 잔여일수 계산이나 공식 인사 기록/HR 시스템 대체
- 관리자 승인 없이 자동 확정 또는 게시
- hard rule 자동 완화 및 위반을 통한 억지 완성
- 의료 기록 저장 또는 진단 정보 기반 배치

## 의사결정 경계
- 시스템은 초안 작성, 가능 여부 안내, 규칙 충돌/미배치 사유 설명까지만 자동 처리한다.
- 관리자가 자동 배치를 검토·수정·확정하고, 확정 후 공개한다.
- 승인된 휴가 정보는 권한 있는 관리자가 일정으로 별도 입력한다. 간호사 신청·결재는 처리하지 않는다.
- 자동 배치 엔진은 hard constraint를 위반하는 결과를 만들지 않는다. 필요 인력이 부족하거나 충돌하면 미배치로 보고한다.

## 제약 및 위험 고려
- 병동마다 근무 유형, 인력 최소 기준, 숙련도/자격 구성, 휴식 규칙이 다를 수 있다. MVP에서 관리자가 정책을 설정할 범위를 정해야 한다.
- 간호사 일정 정보는 접근 권한을 최소화하고 병원/병동 경계를 분리하는 개인정보 보호 설계가 필요하다.
- 병가 등 건강정보를 수집하지 않고 승인된 시간대만 표현하는 최소 데이터 원칙을 권장한다.
- 공식 휴가 결재나 법정 연차 산정은 범위 밖으로 유지한다.
- AI라는 명칭보다 결정적이고 재현 가능한 규칙 엔진 + 최적화 로직이 우선이다. 생성 결과의 이유를 설명할 수 있어야 한다.

## 인수 기준 (초안)
1. 관리자는 월간 달력에서 근무 유형과 간호사 배치를 볼 수 있다.
2. 휴가일, 반차 시간대, 나이트 다음날 데이 배치를 시도하면 시스템이 차단하고 이유를 보여준다.
3. 자동 배치 결과에는 hard rule 위반이 0건이다.
4. 규칙상 채울 수 없는 칸은 비워 두고 충돌 이유를 식별 가능하게 표시한다.
5. 자동 배치가 균등 배분을 최적화하며, 최적화 실패 시 근거를 제시한다.
6. 관리자는 자동 생성 결과를 수정하고 확정/공개할 수 있다. 미확정 초안은 간호사 조회 화면에 나타나지 않는다.
7. 간호사는 공개된 스케줄을 조회할 수 있다.
8. 파일럿에서 월간 편성 작업 시간을 기존 측정 기준 대비 50% 이하로 줄인다. 기준 시간은 파일럿 시작 시 기록한다.

## 가정 및 결정 기록
- “자동 배치”는 시스템이 월간 초안을 만드는 것을 뜻하고, 게시 권한은 관리자에게 남긴다.
- 승인된 휴가 일정은 스케줄 앱이 별도 결재 없이 관리자가 가져와 입력한다.
- 직관적인 색상(가능/불가)과 사유 노출이 편성 지원의 핵심 UX로 제안된다.
- 더 구체적인 근무 규칙, 인원수, 직군, 병원별 정책은 계획 단계에서 사용자 운영정책 입력으로 확정한다.

## 압력 검증 결과
- 수작업 편성 시간만 단축하는 것으로 충분하지 않고, 규칙 위반 위험과 희망사항 취합 난이도가 근본 원인임을 확인했다.
- 자동 배치 도입으로도 관리자의 검토·확정 책임을 제거하지 않는다.
- 불가능한 근무 슬롯은 임의로 규칙을 깨서 채우지 않는다.
- 비목표와 권한 경계를 명시했다: 급여/근태·휴가 승인/공식 HR·자동 게시 제외.

## 기술 컨텍스트
- 코드베이스가 없는 Greenfield 프로젝트. 후속 사용자 결정으로 앱 클라이언트는 Kotlin 사용을 선호하며 Android 네이티브 앱을 우선 가정한다. 서버/API/DB, 최소 OS, UI 방식과 배포 환경은 미정이다.
- 일정 최적화 문제는 설명 가능성과 hard constraint 보장을 우선한다. AI/최적화 라이브러리 선택은 계획 단계에서 검토한다. AI 기반 자동배치는 설명 가능한 제약 최적화로 해석하고, LLM을 근무 규칙 승인자로 사용하지 않는다.

## 후속 사용자 결정 (인터뷰 종료 후)
- 간호사는 병동 전체 달력 또는 본인 일정만 선택할 수 있다.
- 미충원 일정도 관리자가 확인 후 확정 가능하며, confirm 성공 시 활성 달력에 공개 적용한다. 확정 전 초안은 달력에 적용되지 않고 간호사에게 노출되지 않는다.
- API 계약은 병동/object-level 권한 검사, 응답 필드 최소화, revision concurrency, idempotency, 비동기 생성 제한을 기본으로 설계한다.

## 후속 기술 방향 (인터뷰 종료 후 사용자 추가 결정)
- 앱으로 개발하며 Kotlin을 사용할 가능성이 높다고 사용자에게서 확인했다. 현재 계획은 Kotlin Android 앱을 가정하되 플랫폼/서버 설계 선택은 P0에서 확정한다.

## 인터뷰 요약

사용자 응답: 현재 월간 편성 시간은 정확히 모름. 앱 도입 후 기존의 절반 이하가 목표다. 따라서 파일럿에서 현행 엑셀 기준 시간을 기록하고 동일 범위의 편성 작업 시간을 비교한다.
