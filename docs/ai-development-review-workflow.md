# NurseFlow: Claude 개발 · Codex 검토 흐름

## 역할과 산출물

| 담당 | 작업 | 제출물 |
| --- | --- | --- |
| Claude Opus | 요구사항 해석, 기술 설계, API/DB/권한·배치 규칙의 선택지 검토 | 짧은 설계 기록(ADR), 변경할 OpenAPI 항목, 인수 기준, 위험과 롤백 계획 |
| Claude Sonnet | 합의된 설계를 기능 브랜치에서 구현 | 코드, 필요한 테스트, 문서 변경, 검증 결과, PR 설명 |
| Codex | 새 변경분을 독립적으로 읽기 전용 검토 | 재현 가능한 결함 중심의 파일:줄 번호, 영향, 수정안, 검증 근거 |

설계와 구현은 [초기 MVP 범위](mvp-scope.md), [API 계약](openapi.yaml), [Git 흐름](runbooks/git-flow.md)을 공통 기준으로 삼는다. 모델 이름은 개발 도구의 역할을 뜻하며, **근무표 자동 생성의 필수 규칙 판단은 서버 검증기**가 맡는다.

## 기능 단위 작업 순서

1. `dev`의 최신 상태에서 `feat/...` 브랜치를 만든다. Opus가 이 기능의 API·DB·권한·예외 상황과 인수 기준을 먼저 명시한다.
2. Sonnet이 해당 브랜치의 변경 범위만 구현한다. Android, 웹, 백엔드가 함께 바뀌면 OpenAPI와 각각의 응답 모델을 같은 기능 단위로 맞춘다.
3. 구현자는 빌드·필수 규칙/권한 테스트를 실행하고 실제 결과와 실행하지 못한 검증을 PR에 적는다.
4. Codex가 변경된 diff와 관련 호출 경로를 검토하고 한글로 보고한다. 지적된 P1/P2는 `dev` 병합 전에 수정하고 다시 검토한다. P3도 실행 오류 가능성이 있으면 병합 전에 수정한다.
5. 기능 PR을 `dev`로 병합한다. 배포할 때 검증된 `dev`를 PR로 `main`에 반영한다.

같은 폴더를 두 에이전트가 동시에 수정하지 않는다. 독립 작업은 별도 worktree/브랜치에서 진행하며, API 계약을 바꿀 때는 소비자(Android·웹)와 백엔드를 함께 확인한다.

## Codex 리뷰 분류

이 표의 **P1~P5는 리뷰 우선순위**이며 [프로젝트 계획](project-plan.md)의 개발 단계 P0~P5와 다르다.

| 분류 | 검토 기준 | 처리 |
| --- | --- | --- |
| P1 | 권한 우회, 초안/개인정보 노출, 필수 근무 규칙 위반, 데이터 손실·잘못된 공개 | 병합 차단. 재현 조건과 정확한 경로 제시 |
| P2 | 기존 기능 회귀, 동시 편집/월 경계 오류, 잘못된 결과·상태 전이, 보안 통제 누락 | 병합 전 수정 권장. 영향 범위를 명시 |
| P3 | 빈값·null·잘못된 날짜/시간·네트워크 실패 등 런타임 예외 가능성 | 입력과 실행 경로를 제시해 수정 |
| P4 | 핵심 경로 테스트 누락·깨진 테스트·검증 결과와 주장의 불일치 | 필요한 테스트 범위를 구체적으로 제안 |
| P5 | OpenAPI, README, 운영 절차, Figma 흐름과 구현의 불일치 | 실제 사용·유지보수에 영향을 주는 문서 차이만 보고 |

리뷰는 스타일 선호보다 동작·보안·데이터 일관성을 우선한다. 추정만으로 결함이라고 단정하지 않고, 확인된 사실과 아직 검증하지 못한 위험을 구분한다. 같은 미수정 지적을 매번 반복하지 않는다.

## 30분 정기 점검 운영

- 현재 저장소와 `git worktree list`에 나오는 NurseFlow 작업용 worktree(Claude Desktop 포함)의 새 커밋·미커밋 diff를 각각 마지막 리뷰 지점과 비교한다. 변경이 없으면 알림을 보내지 않는다.
- 새 변경이 있으면 변경 파일과 연관 코드·[MVP 범위](mvp-scope.md)·[API 계약](openapi.yaml)만 살펴보고 P1~P5 중 **조치 가능한 발견 사항**을 보고한다.
- 정기 점검은 코드를 수정·커밋·푸시하거나 PR을 병합하지 않는다. 구현자가 수정하면 다음 점검에서 해당 변경을 다시 본다.
- 30분 주기는 작업 중 조기 발견용이다. 병합 직전에는 변경 전체를 대상으로 별도 리뷰와 CI 검증을 실행한다.
- 가상 데이터만 모델과 시연에 사용한다. 실제 간호사 정보, 카카오 토큰, 환경변수·비밀키를 프롬프트나 리뷰 결과에 넣지 않는다.
