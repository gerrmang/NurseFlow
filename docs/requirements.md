# PRD: 병동 간호사 근무표 관리 및 자동 편성

## 상태와 목표
초기 시연 범위는 [MVP 결정](mvp-scope.md)과 [월간 편성 규칙](monthly-roster-rules-and-two-person-plan.md)을 따른다. 기반 명세: [Deep Interview spec](requirements-interview.md). MVP는 Android 앱과 반응형 웹이 같은 Kotlin/Spring Boot API를 사용하며, 가상 데이터와 로컬 H2 DB로 시연한다.

관리자가 엑셀에서 여러 간호사의 일정과 규칙을 일일이 대조하는 시간을 줄인다. 시스템은 규칙 기반으로 월간 근무표 초안을 자동 작성하고, 관리자가 검토·수정·확정·공개한다. 핵심 성공 목표는 월간 전체 편성 작업시간이 기존 엑셀 대비 절반 이하가 되는 것이다. 기준 시간은 모르는 상태이므로 파일럿에서 먼저 측정한다. 안전 규칙 위반이나 검토 누락으로 단축한 시간은 성공으로 보지 않는다.

## 기술 방향(초기 시연 MVP)
- Android는 Kotlin + Jetpack Compose, 웹은 반응형 클라이언트로 구현한다. 두 클라이언트는 같은 Spring Boot REST API를 사용한다.
- 서버는 Kotlin + Spring Boot, 시연용 저장소는 단일 서버의 H2 파일 DB로 확정한다. 실제 병원 배포 DB와 호스팅은 시연 이후 결정한다.
- Kakao OIDC 로그인과 관리자 발급 초대 링크를 사용한다. 로그인만으로 병동 자료를 볼 수 없고, 서버가 병동 membership을 확인한다.
- 오프라인 편성, 푸시 알림, Cloudflare D1/Workers 전환은 초기 MVP 범위에 포함하지 않는다.

## 사용자와 권한
- 관리자(수간호사 등): 초대 링크 발급과 병동 권한 관리, 인력·근무 수요·정책·사전 취합된 확정 불가 일정 입력, 자동/수동 편성, 초안 검토·수정·확정. 확정 시 새 revision이 활성 달력에 공개 적용된다.
- 간호사: 초대 수락·첫 로그인 과정에서 본인의 근무연차·직급을 입력·수정하고 희망 오프를 제출하며, 공개된 근무표를 조회한다. 관리자는 희망 오프를 대신 입력할 수도 있다. 직접 휴가·반차 등록, 희망 오프 외 근무 선호 입력, 신청·결재·표 편집은 이번 MVP 범위 밖.
- 간호사는 병동 전체 달력 보기와 본인 일정 보기 사이를 전환할 수 있다. API별 접근 권한을 서버에서 확인한다.
- 초대받지 않은 로그인 사용자는 병동 데이터에 접근할 수 없다.

## 사용자 흐름
1. 관리자가 초대 링크를 발급한다. 사용자는 Kakao 로그인 후 초대를 수락하며, 서버가 병동 소속·역할·간호사 연결을 생성한다. 가입·첫 로그인 흐름에서 근무연차·직급을 입력받아 1~5 경력 단계를 계산하고 병동 내 팀 소속을 확인한다.
2. 관리자가 병원별 근무 시각·시간 환산, 병동 팀 수·팀별 필요 인원, 개인별 근무 형태·Night 전담 순환, 월 목표시간·SOF·연속근무 규칙을 설정한다.
3. 관리자가 사전에 취합·확정된 휴가·반차를 시간 구간으로 등록한다. 휴가 사유나 진단 정보는 받지 않는다.
4. 자동 초안 생성 또는 수동 배치 수행. 같은 규칙 검증기가 배치 가능 여부, 규칙 코드, 설명을 표시한다.
5. 자동 배치는 hard rule을 지키고 미충원과 상태를 구분한다.
6. 관리자가 초안과 팀별 근무 경력 구성·공정성·미충원 요약을 검토하고 수정한다.
7. 서버가 최신 정책/일정 버전으로 재검증한다.
8. 관리자가 최종 확인/확정하면 서버가 최신 규칙으로 재검증하고 그 revision을 원자적으로 공개해 활성 달력에 적용한다. 미충원이 있어도 관리자가 확인한 뒤 확정할 수 있다.
9. 이후 변경은 새 draft에서 검토·수정한 뒤 다시 확정하며, 초안은 간호사 달력에 보이지 않는다.

## MVP 요구사항
- 초대 수락한 활성 간호사만 편성하고 관리자 계정은 제외. 병동별 팀 개수와 팀별 필요/배치/미충원 인원을 설정·표시.
- 병원별 3교대 시작·종료 시각, 실제 근무시간과 월간 환산시간, 주말·공휴일 기반 월 목표시간을 설정·계산.
- 간호사별 일반 3교대, Day/Evening 전담, Night 전담(인원·순환 주기·Night 횟수)과 Night 횟수에 따른 SOF 정책을 설정.
- 승인된 VY 연차와 별개로 희망 오프를 취합하고 연속근무 상한을 월 경계까지 검증.
- 실제 시간 구간으로 근무, 승인된 전일 휴가, 반차 등록.
- 수동 배치 시 날짜·시간별 가능/불가와 이유를 즉시 제공.
- 정해진 hard rule 기반 월간 자동 초안 생성.
- 균등 배분을 soft objective로 최적화하고 미달 이유를 설명.
- 같은 날짜·근무·팀의 인원이 1~5 경력 단계에 가능한 한 고르게 분포하도록 자동배치와 수동배치 안내에 반영하고, 구성 미달 이유를 표시.
- 다른 팀 간호사의 지원근무는 병동 관리자가 허용한 간호사·대상 팀·근무 범위에서만 허용하고, 허용되지 않은 팀 간 배치는 서버의 모든 경로에서 거부.
- 채울 수 없는 슬롯을 빈 채로 두고 미충원 수와 이유를 표시.
- 자동 생성은 확정 또는 게시하지 않는다.
- 관리자는 초안을 수정하고 확정한다. 확정된 revision은 공개되어 달력에 적용되며, 간호사는 병동 전체/본인 보기를 선택한다.
- 서버 측 병원/병동 권한 검사, 비공개 부재정보 분리.
- 초대 링크의 만료·1회 사용·철회, 가입 시 병동 membership 생성 및 역할 분리.
- Android와 웹에서 같은 공개 revision과 역할별 화면을 제공.

### Hard constraints
- 지정 휴가와 근무 구간 겹침 금지.
- 반차와 근무 구간 겹침 금지(예: 오후 반차는 오후근무 배정 불가).
- 나이트 다음날 데이 배정 금지; 정확한 최소 휴식시간 및 경계 시각은 P0에서 정의.
- 병동 내 다른 팀 근무는 관리자 허용 범위 밖에서 배정 금지. 지원근무를 허용해도 시간 중복·휴가·반차·휴식 규칙은 그대로 적용.
- 허용되지 않은 근무 유형과 연속근무 상한 위반 금지. 월 목표시간 미달은 확정 전 해결하고 불가능하면 원인을 표시하며, 필수 휴식·부재 규칙을 완화하지 않는다.
- 연속근무는 최대 5일이며 다음 날 `OF` 또는 `SOF`가 필요하다. `VY`는 근무일도 연속근무를 끊는 오프도 아니다. 병동이 설정한 팀·근무별 최소 선임 인원을 주니어로 대체하지 않고 미충원으로 표시한다.
- P0에서 합의한 기타 필수 병동 정책.
- 불가 시 빈 슬롯을 유지한다. 자동 완화나 예외 위반 금지.

### Soft objectives
- 근무 수/시간/야간/주말 배분 등 운영자가 확정한 공정성 지표를 개선.
- 병동 내 팀별 각 날짜·근무의 경력 단계 쏠림을 줄인다. 팀 인원과 해당 근무 필요 인원이 5명 미만이면 모든 단계를 채우는 조건으로 해석하지 않는다. 병동 관리자가 연차 구간·직급별 1~5단계 기준을 설정하고 간호사가 가입·첫 로그인 시 입력한 근무연차·직급을 확인한 뒤 계산에 사용한다. 미확인·수정된 프로필은 확인 전까지 경력 구성 점수에서 제외하고 관리자에게 알린다.
- 희망 오프 반영, 개인별 근무 유형·Night·주말 부담의 균등 배분을 개선한다. 미반영 희망 오프와 경력 구성 미달의 이유는 별도로 표시한다.
- 적격 인원·분모·가용시간 보정은 P0에서 정한다.
- hard rule 준수 → 미충원 최소화 → 팀별 경력 구성 개선 → 개인 간 fairness 개선 순서를 기본안으로 검토한다. 경력 구성 미달은 미충원과 별도로 설명한다.
- “최적”은 최적성이 증명된 경우에만 표시. timeout은 불가능 증명이 아니다.

## 결과 상태 구분
- 개별 배치 거부: 이름 있는 규칙과 원인을 설명.
- 초안 미충원: 요구 인원과 부족량 표시.
- timeout/취소/엔진 오류: 완료 여부/불가능 여부 미확정.
- 증명된 infeasible: 솔버가 증명할 수 있을 때만 별도 표시.
휴리스틱 실패나 제한시간 종료로 “유효한 근무표가 없다”고 단정하지 않는다.

## 자동배치 해석
사용자가 요청한 “AI 기반 자동배치”는 먼저 hard constraint를 명시적으로 보장하고 균등 배분 같은 soft objective를 최적화하는 일정 최적화 문제로 다룬다. 생성형 AI/LLM이 근무 규칙을 임의로 해석하거나 예외를 승인하지 않는다. P0에서 결정적 휴리스틱과 제약 최적화 엔진을 같은 조건으로 비교해 구현 방식을 확정한다.

## 비목표
급여·근태·출퇴근, 간호사 직접 불가 일정/선호 근무 등록, 휴가/반차 신청 및 결재, 법정 연차 잔여일수 계산, 공식 HR 대체, 관리자 승인 없는 자동 게시, hard rule 완화, 의료·진단/휴가 사유 수집, 실제 병원 데이터, 폐쇄망 모드, 엑셀 가져오기, 광고·과금.

## 인수 기준
1. 자동 생성·수동 편집·확정·공개 모든 쓰기 경로에서 확정된 hard rule 위반은 0건.
2. 위반 배치는 UI뿐 아니라 API에서도 원자적으로 거부되며 규칙 설명을 반환.
3. 미충원량, 배치 거부, timeout/취소/오류, 증명된 불가능 상태를 구별.
4. 검토 전 초안은 URL/API/export에서도 간호사에게 보이지 않는다.
5. 타 병동 사용자와 간호사는 비공개 부재정보 및 비허용 범위 데이터에 접근할 수 없다.
6. 관리자의 confirm 요청 성공 시 새 revision이 활성 달력에 공개 적용된다. 미충원 표는 부족 슬롯 수를 보여주고 명시 확인을 받아 확정할 수 있다. 초안은 보이지 않고 오래된 revision은 최신 표를 덮지 않는다.
7. fairness 계산이 고정 fixture에서 재현되며, 증명 전 결과는 ‘최적’으로 표시되지 않는다.
8. 파일럿 비교에서 사전에 합의한 표본 조건을 충족하고 전체 월간 작성 시간이 엑셀 기준의 50% 이하. 기준선은 파일럿 전 기록하며 교육/최초 설정 시간은 별도 보고.
9. 시연 MVP에서는 초대받지 않은 Kakao 사용자가 병동에 접근하지 못하고, 초대 수락으로 사용자·병동 소속·간호사 연결이 중복 없이 생성된다.
10. Android와 웹이 같은 API에서 동일한 공개 revision을 읽는다. 시연은 가상 데이터만 사용하며 8번 생산성 수치는 실제 파일럿에서 평가한다.
11. 팀·근무별 1~5 경력 단계의 실제 분포와 구성 미달 이유가 관리자 검토 화면에서 재현된다. 경력 조합을 맞출 수 없어도 hard rule 위반 없이 필요한 인원을 채운 결과는 배치·확정할 수 있다.
12. 팀 간 지원근무는 관리자 허용 범위에 맞는 경우에만 저장·생성·확정된다. 허용 범위 밖 배치는 이유와 함께 거부되고, 허용된 배치는 대상 팀의 충원·경력 구성에 계산된다.
13. 병원별 근무 시각과 환산시간을 변경하면 실제 시간 중복과 월 환산시간이 각각 올바르게 재계산된다. 30일·기준 휴식일 9일·하루 8시간인 예시는 목표 168시간이며, 부족/초과를 구분한다.
14. 활성 초대 간호사만 편성되고 일반/Day·Evening 전담/Night 전담의 허용 근무 유형을 준수한다. 2명이 연속 3개월 Night 전담 후 다른 2명과 교대하고 전담자는 월 Night 최소 15회다. 일반 간호사는 월 Night 6회 이상에 SOF 1일을 받고 전담자는 별도 정책을 적용한다. 최대 연속근무 5일, 희망 오프 미반영, 선임 미충원과 월 목표시간 충돌을 각각 진단한다.

## P0에서 반드시 정할 항목
시연용 가상 병동의 팀·인원·자격 구성과 날짜·팀별 필요 인원, 관리자 허용형 팀 간 지원근무 기록의 정확한 범위·철회 방식, 병동 관리자가 입력할 구체적 연차 경계값·직급 명칭 및 단계 변환 데이터 형태, 단계 분산 점수와 개인 간 균등 배분 산식·대상·분모, 반차 시간 구간, 기존 고정 배치 유지 여부, 공개본 이력/보존·삭제, 동시성 및 성능 한도, Kakao 앱/Redirect URI·초대 링크 연결 방식. 팀 간 지원은 관리자 허용 시에만 가능하고 근무연차·직급의 관리자 확인을 편성에 적용한다는 결정은 확정되었다. 실제 병원 배포용 국가·호스팅·DB·오프라인 요구·추가 병동 정책·엑셀 import/export·비교 파일럿 표본 수는 시연 이후 별도 결정한다.

## 보안 및 개인정보 고려
시간 구간과 필요한 최소 분류만 저장하며 병가·진단 사유는 받지 않는다. 관리자/간호사 역할과 병원/병동 membership은 서버에서 검사한다. 관리자 사유 필드는 간호사 화면에서 분리한다. 보존·삭제·백업·감사 정책은 배포 위치와 병원 요구사항 확인 후 결정한다. 법령·현장 정책 검토 없이 법적 적합성을 보장한다고 표시하지 않는다.
