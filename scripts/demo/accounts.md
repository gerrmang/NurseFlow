# B6 시연 계정 운용과 검증

## 자동 검증용 가상 계정

`run.ps1 -Verify`는 가상 OIDC의 **관리자 1명·간호사 1명, 총 2개 신원**을 사용한다. 비소속 접근 검사는 같은 간호사가 가입하기 전에 수행한다. 별도 제3계정이나 실제 Kakao 계정은 만들지 않는다.

- 관리자는 A/B팀 데이터가 있는 시연 병동을 소유한다.
- 계정 가입 검사는 가상 가입 검증 병동을 하나 더 만든다. 간호사는 가입 전에 404, 관리자 초대 수락 후 WARD_MEMBER 소속과 본인 입사 연월을 확인한다. 관리자 staff/편성 대상 조회는 간호사에게 403이다.
- 가입 검증 병동은 시연 모드를 끈 기본 상태에서 가입한 간호사 1명만 편성 대상으로 판정한다. 관리자에게 간호사 기록이 생기지 않는지도 검사한다. A/B팀 시연 병동의 계정 미연결 간호사 10명은 그대로 유지한다.
- 서명키·ID 토큰·세션은 실행 중 메모리에만 보관하고 종료 때 폐기한다. 원본 토큰·인증 코드·실제 계정 식별자를 로그·Git·검증 보고에 적지 않는다. 매번 새 메모리 DB에서 재현하며 계정 복구 작업은 필요 없다.

## 실제 Kakao 시연 준비안 — 사용자 확인 필요

실제 Kakao 로그인 검증에 사용할 계정의 수·소유·이용 가능 여부는 계정 소유자의 확인이 필요하다. 자동 가상 계정 검증으로 실제 Kakao 2계정 시연까지 통과했다고 표시하지 않는다.

준비안은 **관리자 역할 1개·간호사 역할 1개, 테스트 계정 총 2개**다. 각 계정 소유자가 직접 로그인하며 비밀번호·토큰을 저장소나 채팅으로 전달하지 않는다. 계정 소유자가 사용할 수 있는 테스트 계정과 개발용 Kakao 앱을 확인한 뒤 아래를 수행한다.

1. 기존 파일 DB와 분리한 서버·가상 병동에서 관리자가 직접 로그인하고 초대 링크를 발급한다.
2. 다른 계정으로 로그인한 간호사는 가입 전 타 병동 접근이 거절되고, 일회용 초대를 수락한 뒤 본인 소속·프로필만 허용되는지 확인한다.
3. Android·웹 관리 화면에서 서버 시연 모드와 가상 데이터 포함 경고를 확인한다. 일반 모드로 바꾼 뒤 최신 목록을 조회해 표시가 바뀌는지도 확인한다.
4. 결과에는 실행 환경·성공/실패·서버 커밋만 기록한다. 실제 계정명·연락처·토큰·링크 원문은 남기지 않는다. 종료 시 세션·초대·검증용 DB를 폐기한다.

현재 기록은 **가상 2계정 자동 검증 완료 / 실제 Kakao 2계정 시연 미실행**이다. 사용자에게 요청한 운용 방식 선택 전까지 결정 21을 임의로 해결 처리하지 않는다.
