# breakdown 전 제품 범위와 미결정 사항

상태: 2026-11-04 기획 재정립. [초기 MVP 범위](mvp-scope.md)를 보완한다. 이 문서는 기능별 PR이나 담당자를 아직 나누지 않는다. 첨부 메모에서 확정된 사용자 지시와 예시 엑셀에서 추정한 제안을 구분한다. 최신 `dev`의 런타임 구현 완료를 뜻하지 않는다.

## 확정된 사용자 흐름

1. 최초 스케줄 관리자는 Kakao로 로그인하고 **실제 병원 검색 결과를 선택**한 뒤 병동명을 입력해 자기 병동을 만든다. 생성자는 해당 병동의 `WARD_ADMIN`이다. 별도 `HOSPITAL_ADMIN` 역할은 제품 흐름에 두지 않는다. 병원 선택은 재직·소속 증명이 아니며 병동 ID·권한은 서로 분리한다. 같은 병원을 다른 관리자가 선택해도 기존 병동의 권한을 얻지 못한다.
2. 관리자는 병동 초대 링크를 발급·복사·공유한다. 유효기간은 **24시간 고정**, 1회 사용이며 만료·철회된 링크로 가입할 수 없다. 새 링크를 발급할 수 있다. 기존 코드의 1~168시간/기본 72시간은 이 결정에 맞춰 변경이 필요하다.
3. 초대받은 간호사는 Kakao 로그인 뒤 초대를 수락하고 자기 **입사 연월**을 입력한다. 간호사가 직급명을 직접 고르는 입력은 없앤다. 관리자는 입사 연월을 확인하고 병동의 경력 단계·선임 자격을 별도로 지정·조정한다. 수동 조정 값은 원래 입사 연월을 덮어쓰지 않으며 변경 이력을 남긴다.
4. 로그인 뒤 병동 목록에는 본인이 속한 병동과 각 병동의 역할(관리자/간호사)을 함께 보여준다. 최근 선택한 병동을 위에 두더라도 서버에서 다시 소속·권한을 확인한다. 간호사는 초안이 아니라 관리자가 확정한 병동 전체/본인 근무표를 조회한다.
5. 관리자는 팀 수와 팀원을 편성 전에 설정한다. 입사 연월 기반 경력 정렬을 기본으로 제공하되, 병동 운영에서 쓰는 편성 순서·선임 자격은 관리자가 조정할 수 있다. 팀 소속과 편성 순서는 별도 데이터다. **각 팀의 각 Day·Evening·Night에 선임 자격자 최소 1명**을 둔다. 부족하면 선임 필요 칸을 미충원으로 표시한다.
6. 자동 생성은 필수 규칙을 지킨 비공개 초안만 만든다. 관리자가 후보 불가 이유·미충원·경력 구성·개인별 시간을 검토하고 수정·재검증한 뒤 확정한다. 확정 전 간호사 화면에는 초안을 공개하지 않는다.

### 실제 병원 검색 연동

- 초기 개발 범위에 **외부 병원 검색 API의 실제 연결**을 포함한다. 전체 병원 목록을 웹에서 긁어 로컬에 복제하지 않는다. 1차 데이터원은 [건강보험심사평가원 병원정보서비스](https://www.data.go.kr/data/15001698/openapi.do)로 검토한다. 이 공식 API는 요양기관 신고 기준 병원 정보를 REST/XML로 제공하며 병원 식별자는 암호화된 요양기호다. 개발 활용은 자동 승인, 운영 활용은 심의 승인으로 안내돼 있으므로 실제 키·운영 승인·호출 한도는 연동 전에 확인한다.
- Android·웹은 NurseFlow 백엔드의 검색 API를 호출한다. 백엔드가 외부 서비스 키를 보관하고 병원명·주소·외부 식별자·데이터원만 필요한 만큼 정규화해 반환한다. 검색어 입력→후보(동명이면 주소 표시) 선택→병동명 입력→관리자 생성 순서다. 선택한 외부 식별자와 표시명 스냅샷을 저장하되, 검색 결과 선택만으로 병원 전체 권한이나 실제 재직 인증을 부여하지 않는다.
- 외부 API 장애·검색 결과 없음·중복 이름을 각각 표시한다. 개발용 가상 응답으로 화면을 검증할 수 있지만 실제 검색 연동 완료를 주장하려면 외부 API 호출과 키 관리·오류·속도·데이터 출처 표시를 확인한다. 검색 결과가 없는 기관의 수동 등록 허용 범위는 별도로 결정한다.
- Google Maps나 지도 데이터 전체 수집은 필수 조건이 아니다. Google Places는 [별도 과금·인증 방식](https://developers.google.com/maps/documentation/places/web-service/usage-and-billing/)을 가지므로, 공식 병원 목록의 검색 품질이 부족할 때 대안을 비교한다.

## 근무 정책과 범위

- D/E/N의 실제 시작·종료 시각, 휴게, 월간 환산시간과 VY/SOF 등의 인정시간은 **병동 관리자가 설정**한다. 엑셀의 D/E 7.5시간, N 9시간, VY/SOF 8시간은 시연 예시로만 사용한다.
- 특수 코드 `DD`, `DE`, `ET`, `DK`, `DN`, `T2`, `CC`, `VR`, `VX` 및 부분 휴무 코드 `V9`, `VV`, `VS`, `VE`는 의미를 추정하지 않는다. 관리자가 코드별 근무/휴무 종류, 실제 시간 구간, 환산시간, 연속근무·충원 계산 포함 여부를 정의해야 자동배치에 사용한다.
- 관리자 계정은 편성 대상에서 제외한다. 초대 수락한 활성 간호사 중 이번 달 대상 여부, 일반/Day·Evening 전담/Night 전담, 팀 소속과 지원 허용을 서버에서 판정한다.
- Night→다음 날 Day와 Evening→다음 날 Day 금지는 현재 서버에 구현된 필수 규칙이다. 최대 연속근무 5일, 6일째 `OF`/`SOF`, 월 경계 검사와 팀별 선임 필요 인원은 구현할 필수 규칙이다. `VY`는 앞서 확인된 결정대로 근무일도 연속근무 초기화일도 아니다.
- 일반 간호사 월 Night 6회 이상 → 같은 달 SOF 1일은 기존 결정이다. Night 전담은 별도 정책을 사용한다. SOF의 다음 달 이월, 시간 잔여 이월, 공식 연차 원장은 아직 확정되지 않았고 초기 MVP에 자동 포함하지 않는다.
- 공식 연차 승인 자체는 앱 밖에서 끝난다. 관리자가 이미 승인된 `VY`·반차 일정만 등록하고, 간호사가 앱에서 신청하는 것은 별도의 **희망 오프**다. 희망 오프는 간호사 또는 관리자가 제출하고 관리자가 확정·반려한다. **제출 후 미확정 날짜는 선호 목표, 확정된 날짜는 해당 간호사의 배치 금지**다. 반려된 날짜는 고정 오프가 아니다. 상태와 판단 시각을 기록한다.
- 월 목표시간은 주말·공휴일 중복을 제거한 병동 달력과 일일 기준시간으로 계산하고 관리자가 조정한다. 실제 근무시간과 환산시간은 별도 표시한다. 일반 직원 목표 미달 금지와 D/E 전담의 허용 오차는 병동 정책으로 명시한다. 52시간 등 법적 상한은 적용 기관·산정법을 검증하기 전 코드 상수로 고정하지 않는다.
- Android와 반응형 웹은 **초기 MVP의 공통 API 클라이언트**다. iOS는 후속 플랫폼이다. 엑셀 내보내기와 AI를 이용한 가져오기는 서로 다른 기능이며 둘 다 초기 MVP 밖의 후보로 둔다.

## 남은 결정

- 검색 결과가 없는 기관을 관리자 임시 입력으로 허용할지, 별도 확인 요청으로 처리할지. 실제 병원 검색 API 연동 자체는 초기 개발 범위로 확정했다.
- 병원명이 같은 별도 병동 공간을 어떻게 표시할지, 병동 관리자 계정을 잃었을 때 다른 관리자가 이어받는 절차. 기존 병동에는 초대로만 참여한다는 권한 경계는 고정한다.

추가 `SOF` 이월·잔여시간 이월·공식 연차 원장·법정 상한 자동 판정은 첨부 메모의 제안으로 보존하되, 기존 MVP의 확정 범위로 승격하지 않는다.
