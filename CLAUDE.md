# NurseFlow project context for Claude Code

- Claude and Codex share the repository rules, active task branch/worktree, feature sequence, progress record, and review/verification procedure in `AGENTS.md`, `docs/feature-breakdown.md`, `docs/work-status.md`, and `docs/ai-development-review-workflow.md`. On handoff, continue the same worktree and preserve existing edits; do not create a second checkout for the same task. `docs/claude-next-stage.md` contains architecture guidance, not a Claude-only task sequence.
- Before starting or resuming, follow `AGENTS.md`, check the current feature and owned paths in `docs/feature-breakdown.md`, progress in `docs/work-status.md`, and `git status --short --branch`. The breakdown is the current task sequence.
- For product scope, read `docs/mvp-scope.md` and `docs/monthly-roster-rules-and-two-person-plan.md`; read `docs/requirements.md`, `docs/openapi.yaml`, `docs/project-plan.md`, and `docs/test-plan.md` as needed. The latest confirmed user decisions win where older planning text differs.
- Follow `docs/ai-development-review-workflow.md` for review priority, Codex's review-versus-implementation role, and review records. It describes a 30-minute review cadence; do not describe that cadence as an active automated check unless the automation is verified as configured and running.
- The repo has `backend/` (Kotlin Spring Boot + local H2) and `android/` (Kotlin Compose). Android Kakao login and NurseFlow session/ward-list integration (B1) are implemented and merged in PR #30; see [`android/B1-verification.md`](android/B1-verification.md) for its recorded local, device, and real-login checks and remaining unverified cases. The roster demo still uses local `DemoRoster` data. The web client is not implemented.
- Before edits, inspect `git status --short --branch` and remote branch heads. For an existing task, continue its active branch/worktree. For a new feature, start from the latest `dev` on a work branch and preserve unrelated changes.
- The server is authoritative for roster constraints and publication. Ward administrators enter approved leave and half-day intervals. Nurses may submit preferred days off; administrators can also submit on their behalf, then review/confirm or reject them. Preferred days off are separate from approved leave and half-days.
- Use fictional demo staff only. Never place Kakao credentials, real nurse information, or leave reasons in code, fixtures, logs, prompts, or commits.
- Work in small feature branches from `dev`. Submit feature PRs to `dev`; release with a reviewed `dev` to `main` PR. Do not merge or push to `main` directly.
- Follow the current feature's boundaries and acceptance criteria in `docs/feature-breakdown.md`. Keep one reviewable feature unit per branch and PR; do not start a dependent unit before its stated prerequisite is met.
- For backend errors and identity, follow `docs/backend-error-auth-dto-conventions.md`: stable ErrorCode/BusinessException, central MVC and security-filter error responses, explicit actor passing to services, and Kotlin request/response data classes.
- GitHub에 올리는 커밋 제목·본문과 PR 제목·설명, 사용자에게 보여주는 검토 보고는 가능한 한 한글로 작성한다. `feat`·`fix` 같은 유형과 Git trailer 키, 코드 식별자만 원문을 유지한다.
