# B6 가상 데이터 시연

최신 backend의 **공개 HTTP API**로 가상 병동·팀·간호사·근무 유형을 생성한다. 실서버 연동 기준은 dev `139b609`이다. Spring의 인증 서명 검증·권한·API·DB 구현을 그대로 사용하며 OIDC 공급자·계정·병원 목록만 가상이다.

## 실행

Windows PowerShell, Node.js 22 이상, JDK 21(`JAVA_HOME` 설정)이 필요하다. 저장소 루트에서:

```powershell
.\scripts\demo\run.ps1
```

이 한 명령이 `backend`의 `bootJar`를 빌드하고, 루프백 가상 JWKS 공급자와 별도 메모리 H2의 Java 서버를 시작한 뒤 데이터를 채우고 다시 조회해 검증한다. Gradle 의존성이 이미 캐시에 있으면 `-Offline`을 붙일 수 있다. 기본 API 주소는 `http://127.0.0.1:18096`, 충돌 시 `-Port 18097`처럼 바꾼다. 기존 포트의 프로세스를 종료하지 않는다.

실행 후 터미널을 유지한다. `r` + Enter는 같은 병동을 다시 조회하고 누락 단계를 복구하며, 완료 상태에서는 조회만 한다. `q` + Enter 또는 Ctrl+C로 이번 Java·JWKS 서버를 종료하고 **메모리 DB를 폐기**한다. 터미널 입력이 닫혀도 종료한다. 매번 새로 명령을 시작하면 새 DB가 만들어진다. 고정 시연 데이터의 사용자 변경값은 일부 필드가 다시 적용될 수 있으므로 전용 런타임에서만 사용한다.

macOS/Linux에서는 JDK 21로 `backend/gradlew bootJar`를 실행한 뒤 다음처럼 Node 진입점을 사용할 수 있다(이번 검증은 Windows만 실행).

```sh
node scripts/demo/local.mjs --jar backend/build/libs/nurseflow-backend-0.1.0-SNAPSHOT.jar
```

## 생성 결과

| 항목 | 내용 |
| --- | --- |
| 병원·병동 | B6 가상병원 / B6 가상 시연 병동 |
| 팀 | 가상 A팀·가상 B팀 |
| 간호사 | 팀별 가상 간호사 5명, 편성 단계 1~5 각 1명, 총 10명 |
| 경력·선임 | 가상 실제 경력 입력·확인, 단계 명시 조정, 4·5단계 선임 지정 |
| 팀 안 순서 | 5→4→3→2→1단계 순서로 저장 |
| 근무 | D 07:00~15:00 / E 15:00~23:00 / N 23:00~다음 날 07:00 |
| 시간 | 각 구간 480분, 휴게 30분, 인정·목표 환산 450분(시연값) |
| 편성 대상 | 계정 미연결 가상 기록 10명, `demoMode=true`, 서버 판정 ELIGIBLE |

단계는 `stageOverride`로 고정한다. 실제 경력 시작 연월은 가상 이력이며 단계·선임 자격을 자동 추정하는 정책이 아니다. 병원 입사 연월은 계정 가입 전이므로 비어 있다. 직급은 서버 병동 정책의 첫 항목을 사용한다.

## 데이터·권한·복구

- `hospitals-fictional.csv`는 기존 병원 importer가 요구하는 **CP949** 형식의 1행짜리 가상 fixture다. 기존 설정 인터페이스로만 전달하며 공식 병원 데이터·실제 이름·연락처·휴가 사유·건강정보를 사용하지 않는다. `HIRA`는 현행 API가 허용하는 출처 식별자이며 이 파일이 공식 데이터라는 뜻은 아니다.
- DB는 Java 프로세스 안의 `jdbc:h2:mem:b6_fictional`이다. 사용자 루트·backend 파일 DB, 기존 서버 환경변수, 배포 설정은 사용하지 않는다. Java 환경을 제한하고 Spring 설정 위치·루프백 바인딩·병원 경로를 명시한다. 서버 내부 SQL 시드·인증 우회·근무 규칙 변경은 없다.
- 서명키·세션 비밀값·토큰은 실행 중 메모리에만 둔다. ID 토큰 발급용 HTTP 경로는 없으며 JWKS 공개키만 노출한다. 토큰·원본 요청/응답·Java 로그는 출력하지 않는다. 오류는 HTTP 상태와 재실행 안내만 표시한다.
- 생성은 직렬 실행한다. 병동·근무 유형은 멱등 키를 사용하고 정책 쓰기는 조회한 ETag를 보낸다. 결과 유실·401·403·409·412·서버 오류 때 임의 재전송하지 않는다. 다음 `r`에서 목록을 다시 조회한다. 팀·간호사 생성 응답을 잃어도 고유 가상 이름으로 복구한다. 같은 이름이 여러 개거나 예상 밖 팀·간호사·근무 유형이 있으면 중단한다. 기존 근무 시간 설정이 다르면 덮어쓰지 않는다. 두 프로세스로 같은 병동을 동시에 채우는 방식은 지원하지 않는다.
- 터미널에 `[시연 모드 ON / 가상 데이터]`를 표시한다. **Android·웹의 시연 모드 배너·설정 UI는 아직 없으며 이번 B6 스크립트 범위 밖**이다. 실제 Kakao 로그인이나 앱/웹에서 이 가상 OIDC 계정으로 로그인하는 기능도 제공하지 않는다. 실제 계정 시연은 breakdown 결정 21(계정 수·관리) 확정 후 별도 작업이다.
- 초안·필요 인원·자동배치·확정·공개는 생성하지 않는다. B7·B10·B12에서 이어간다. 이번 시연의 역할은 API 데이터 준비·재현이며 클라이언트 시연 완료를 뜻하지 않는다.

## 검증

빠른 오류 처리·포트 보호 검사:

```powershell
node --test scripts/demo/api.test.mjs scripts/demo/runtime.test.mjs
```

새 H2와 실제 backend를 사용하는 통합 검증(완료 후 자동 종료):

```powershell
.\scripts\demo\run.ps1 -Verify -Offline
```

병동·팀·간호사·근무 유형의 성공 응답을 차례로 유실시킨 뒤 재개한다. 최종 조회로 팀·경력·단계·선임·순서·D/E/N의 모든 시간 필드·서버 편성 대상 10명을 확인한다. 완료 후 재실행 쓰기 0건, 오래된 정책 ETag 412, 시연 모드 해제 시 전원 `DEMO_MODE_DISABLED`, 비소속 계정 조회 404 및 시연 모드 복구를 검증한다. 기존 Day 인정시간을 변경한 상태에서는 시드가 덮어쓰지 않고 거절하는지도 확인한다. 실제 Kakao·기기·운영 환경 검증과 구분한다.

API·DB 스키마·환경변수 계약 추가·배포 영향 없음. 시연 설정은 이번 Java 자식 프로세스에만 적용된다. 되돌리기는 시연 종료 후 이 스크립트 변경을 제거하거나 해당 커밋을 revert하면 된다. 사용자 DB 복구는 필요 없다.
