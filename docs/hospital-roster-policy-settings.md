# 병원·병동 근무 정책 설정 명세

상태: **2026-11-02 요구사항 초안, 런타임 미구현**. 관리자 설정 화면·DB·API·자동편성에 연결하기 위한 입력 목록이다. 이 문서만으로 정책이 앱에서 동작하지 않는다. 기본 범위는 합성 데이터 시연이며, 병원별 숫자와 법령 적용은 관리자 설정·기관 확인 전까지 고정하지 않는다.

상세 편성 기준은 [월간 근무표 규칙](monthly-roster-rules-and-two-person-plan.md), 제품 범위는 [MVP 범위](mvp-scope.md)를 따른다. 충돌 시 사용자가 앞서 명시적으로 확정한 기준을 유지한다.

## 관리자 설정 화면

입력은 `병원 기본 정책 → 병동별 적용/예외 → 월별 수요·대상자` 순서로 구성한다. 설정 화면은 저장 전 검증 결과와 변경 영향을 보여주고, 저장 시 정책 버전을 올린다. 근무표 생성 작업은 시작 시점의 정책 버전과 대상자·수요 revision을 함께 고정한다. 이미 생성된 초안은 정책 변경만으로 조용히 바꾸지 않고 재검증 대상으로 표시한다.

| 설정 묶음 | 입력 필드 | 입력/검증 규칙 |
| --- | --- | --- |
| 편성 대상 | 활성 초대 수락 간호사, 이번 달 포함 여부, 편성 제외 여부·관리자 계정 여부 | 활성·수락·해당 병동 소속 간호사만 대상. 관리자 제외는 서버에서 강제하고 화면 선택으로 해제할 수 없다. |
| 팀 | 팀 개수, 팀 이름, 간호사별 소속 팀, 팀별 날짜·근무별 필요 인원 | 팀 수와 이름은 병동별 설정. 0 이상 정수, 대상 간호사의 유효한 소속 여부 확인. |
| 근무 유형 | 코드, 표시 이름, 종류(DAY/EVENING/NIGHT/기타), 시작·종료 시각, 자정 통과, 휴게 분, 실제 인정 시간, 월 목표 환산 시간 | 시간대 겹침·종료 시각·휴게 범위를 검사한다. 실제 근무시간과 목표 환산시간은 별도 보관한다. 지원되지 않는 코드의 뜻은 관리자가 정의하기 전까지 추정하지 않는다. |
| 특수 근무 코드 | 병원 정의 코드(예: 교육·파견·상근), 표시 이름, 적용 대상, 가능 날짜, 실제/환산 시간, 근무일·휴식일 계산 방식 | 병원 관리자가 명시적으로 등록한 코드만 허용한다. `DD`, `DE`, `ET`, `DK` 등 엑셀 코드를 자동 매핑하지 않는다. |
| 휴가·반차 코드 | 승인 일정 종류, 적용 시작·종료 시각, 오전/오후/사용자 지정 시간 구간, 근무 가능 여부, 목표시간 환산값 | 승인 일정은 관리자가 입력한다. 해당 시간과 실제 근무가 겹치면 불가. 시간대와 환산값은 병원 정책. 사유·건강 정보는 수집하지 않는다. |
| 경력·선임 | 연차 구간·직급→1~5단계 기준, 선임으로 인정할 단계, 팀·근무별 최소 선임 수 | 병동 관리자가 설정하고 간호사 프로필을 확인한 이후에 편성 점수에 사용. 최소 선임 수는 필수 조건이며 부족하면 선임 미충원으로 표시한다. |
| 근무 자격 | 간호사별 일반 3교대/Day·Evening 전담/Night 전담, 허용 근무 유형 | 비허용 유형은 후보·수동·자동·확정 모든 경로에서 서버가 금지한다. 건강 사유는 저장하지 않는다. |
| Night 전담 | 전담 인원 수, 순환 주기(월), 전담 조 유지 기간, 월 최소 Night 수, 전담 월 목표시간, Night 환산시간, 별도 휴식 정책 | 사용자 결정 기본안은 2명씩 3개월 블록 순환·월 Night 최소 15회. 설정 변경은 명시적 병원 정책 버전으로 관리한다. |
| SOF | 일반 직원 Night 임계 횟수, 부여 일수, Night 전담 별도 규칙, SOF 환산시간 | 사용자 결정 기본안은 일반 직원 월 Night 6회 이상이면 같은 달 자유 날짜에 1일. Night 전담은 별도 정책. 해당 기준은 기본 시연값으로 병원별 변경 가능. 이월은 현재 확정 범위에 포함하지 않는다. |
| 연속·교대 휴식 | 최대 연속 근무일, 연속 Night 상한(2 또는 3 등), 교대 간 최소 휴식 시간, 패턴별 금지 여부 | 사용자 결정 기본안은 최대 5일 연속 근무, 6일째 `OF`/`SOF`. 추가 Night/E-D/N-E 제한은 병원에서 값을 확정하고 활성화하기 전까지 법적·보편 규칙으로 단정하지 않는다. 활성화 후에는 서버 hard rule로 모든 편성 경로에 동일 적용한다. |
| 신청 오프·주말 휴무 | 개인 월 최대 희망 오프 수, 주말(토/일) 최소 희망 휴무 횟수, 신청 마감 | 희망 오프는 승인 휴가와 분리된 선호 항목. 한도·주말 목표는 병동 설정이며, 충원과 충돌하면 가능한 한 반영하고 미반영 이유를 보여준다. |
| 휴일·월 목표 | 시간대, 주말·공휴일 달력, 대체휴일·병동 예외, 기준 일일 시간, 일반/전담 개인 목표시간 | 목표 환산시간은 병원 달력 정책으로 계산한다. 실제시간·환산시간·목표·잔여·초과를 분리 표시한다. Night의 월 귀속 규칙도 명시한다. |
| 목표 미달 허용 | 대상 근무 유형/직원 분류, 최대 미달 시간(음수 허용 오차) | 일반 직원의 목표시간 음수 잔여를 허용하지 않는 것이 현재 합의안이다. D/E 전담 등 목표가 수학적으로 불가능한 분류에 음수 허용을 두려면 별도 정책으로 대상·최대 미달량·확정 시 경고/차단 기준을 설정한다. 음수 허용을 전체 간호사에 적용하지 않는다. |
| 주간 근무시간 상한 | 산정 주 시작일, 주 최대 실제 근무시간, 예외 대상·정책 버전 | 첨부안의 52시간은 법령 적합성을 확인하지 않은 채 코드에 상수로 넣지 않는다. 국가·기관·직원 유형에 적용되는 한도와 산정 방법을 적법하게 확인한 뒤 활성화한다. |

## 자동 편성 엔진 적용 방식

### 필수 제약

- 승인된 부재 시간 겹침, 같은 시간대 중복, Night 다음날 Day 금지.
- 간호사별 허용 근무 유형, 관리자 계정 제외, 명시적 팀 간 지원 허용 범위.
- 사용자가 확정한 최대 연속 근무 5일 및 OF/SOF 휴식 규칙.
- 관리자가 설정한 팀·근무별 최소 선임 인원.
- 활성화된 병원별 시간/교대 휴식 제한과 확인된 주간 근무시간 상한.

희망 오프를 첨부 문구처럼 “최우선 고정”으로 승격하지 않는다. 앞서 확정한 기준대로 신청 오프는 가능한 한 반영하는 소프트 목표이고, 승인된 휴가·반차만 배치 불가다. 첨부 문구의 VY가 연속근무를 초기화한다는 안도 채택하지 않는다. 기존 사용자 결정대로 `OF`·`SOF`만 연속근무를 끊고, `VY`는 근무일도 휴식 리셋일도 아닌 별도 상태다.

### 소프트 목표와 충돌 진단

- 희망 오프, 주말 휴무, 근무 횟수·시간 균형, 팀·근무별 확인된 1~5단계 분산은 점수화 목표로 둔다.
- 정해진 팀별 인원, 월 목표시간, Night 전담 최소 횟수처럼 필수인지 선택인지 병원 정책이 결정해야 하는 목표는 정책에 성격을 명시한다. 필수로 선택된 경우 불가능하면 자동으로 풀지 않고 생성 불가/미충원 사유를 반환한다.
- 자동 편성은 위반 점수만 최소화하는 방식으로 hard rule을 완화하지 않는다. 불가능한 조합은 누락 규칙 이름, 대상 날짜·근무·팀, 부족 인원/시간을 관리자에게 보여준다.
- 후보 안내, 수동 저장, 자동 생성, 확정이 동일한 서버 정책 버전으로 재검증한다. 간호사 공개 달력은 관리자가 확정하기 전까지 변경하지 않는다.

## 첨부 내용과 기존 합의의 조정

| 첨부 제안 | 적용 결정 |
| --- | --- |
| 팀, 근무시간·휴게, 근무별 필요 인원, 특수 코드, 반차 환산 설정 | 관리자 설정 필드 목록에 추가. 실제 설정 API/UI는 아직 미구현. |
| 개인별 최대 희망 오프와 최소 주말 휴무 | 병동별 소프트 목표 설정으로 추가. 희망 오프는 필수 휴가 고정 규칙이 아님. |
| Night 연속 상한, E-D 금지, N-E 최소 휴식 | 병원에서 값·적용 여부를 결정하는 정책 필드로 추가. 기본값을 임의로 확정하지 않음. 기존 N→다음 날 D 금지는 이미 확정된 기본 hard rule. |
| 주 52시간 hard limit | 운영 법령·산정법 확인 전에는 활성화하지 않음. 확인된 상한만 설정 가능한 정책으로 둠. |
| VY를 연속근무 reset으로 계산 | 기존 결정과 상충하므로 미적용. OF·SOF만 reset. |
| 희망 오프를 1순위로 고정 | 기존 결정과 상충하므로 미적용. 승인된 부재는 hard constraint, 희망 오프는 best-effort. |
| 일반 목표시간 음수 금지와 D/E 전담 예외 | 일반 직원 기준은 유지. D/E 전담의 최대 허용 미달은 별도 설정을 두되 병원 승인 전까지 기본 예외값은 미정. |
| SOF 이월 | 같은 달 자유 날짜에 배치한다는 기존 결정 유지. 이월 설정은 초기 MVP에 넣지 않음. |

## 미구현 경계 및 다음 단계

현재 구현은 근무 정책 설정 화면/API를 제공하지 않는다. DB에는 `shift_types`와 승인 부재·초안 수요만 있고, 휴게/환산시간·팀·선임/근무 유형 권한·SOF·목표시간·휴일 달력·희망 오프·설정 가능한 연속근무/주간 상한을 저장하지 않는다. 서버 validator는 승인 부재 겹침, 동시간 중복, Night 다음날 Day만 판정한다. 따라서 본 문서의 추가사항은 **요구사항으로 정리된 것**이며 실행 정책으로 적용 완료된 것은 아니다.

구현 순서는 설정 읽기/쓰기 DTO와 병원 정책 revision 계약 → 관리자 설정 화면 → 저장/권한/유효성 검사 → validator 공통 입력화 → 각 규칙 단위 테스트 → 자동 생성 최적화 순으로 기능별 PR로 나눈다. 첫 기능 PR은 설정 묶음 전체를 한 번에 구현하지 않고 `근무 유형·시각·휴게·환산시간`처럼 하나의 검증 가능한 범위만 다룬다. API 경로·요청/응답 스키마는 구현 PR에서 `docs/openapi.yaml`에 추가한다.
