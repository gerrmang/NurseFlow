# NurseFlow 초기 시연 MVP 범위

상태: **2026-10-29 사용자 결정 반영**. 이 문서는 초기 MVP의 제품 범위를 정한다. [기존 PRD](requirements.md)와 [프로젝트 계획](project-plan.md)의 일반적인 설명보다 이 문서의 명시적 결정이 우선한다. 실제 병원 도입용 정책·보안 적합성을 승인한 문서는 아니다.

## 목표와 시연 조건

- 가상 병원·병동·간호사 데이터로 월간 3교대 근무표를 작성한다.
- 관리자가 사전에 취합한 **확정된 휴가·반차 일정**을 시간 구간으로 등록한다. 사유·진단 정보는 받지 않는다.
- 자동 배치는 필수 규칙을 지킨 초안만 만든다. 관리자가 가능/불가 사유, 미충원, 균등 배분을 보고 수동 수정한 뒤 확정·공개한다.
- Android 앱과 반응형 웹에서 **같은 Spring Boot API와 공개 revision**을 사용한다. 관리자와 간호사의 핵심 흐름을 두 클라이언트에서 모두 제공한다.
- 초기 시연에는 실사용 병원 직원 정보를 넣지 않는다. 엑셀 대비 작성시간 50% 이하 목표는 실제 파일럿에서 기준 시간을 측정한 뒤 평가한다.

## 확정된 기술·운영 결정

| 항목 | 초기 MVP 결정 |
| --- | --- |
| Android | Kotlin + Jetpack Compose |
| 웹 | 반응형 웹 클라이언트. 구체적인 프레임워크는 구현 선택으로 둔다. |
| 공통 서버 | Kotlin + Spring Boot. 클라이언트는 서버의 동일 API 계약을 사용한다. |
| 시연 DB | 서버의 로컬 H2 파일 DB. 하나의 서버 인스턴스로 운영한다. |
| 운영 DB/호스팅 | 초기 시연 범위 밖. 실제 병원 도입 전에 PostgreSQL 등 운영 저장소, 배포 위치, 백업·보존 정책을 별도 결정한다. Cloudflare D1/Workers 전환은 이번 MVP에 포함하지 않는다. |
| 로그인 | Kakao OIDC 로그인. 로그인 자체는 병동 권한을 주지 않는다. |
| 가입 | 관리자가 만든 병동 초대 링크를 수락해야 병동 소속과 역할이 생긴다. |
| 근무 | Day 07:00–15:00, Evening 15:00–23:00, Night 23:00–다음 날 07:00을 시연 기본값으로 둔다. 관리자가 편성 전에 근무 유형과 날짜별 필요 인원을 설정한다. |
| 시간대 | 시연 병동은 Asia/Seoul. Night가 월 경계를 넘는 경우에도 전·다음 달 공개 근무를 검증한다. |

## 계정과 권한

| 상태/역할 | 허용 작업 |
| --- | --- |
| Kakao 로그인만 완료 | 본인 세션 확인, 유효한 초대 수락. 병동 데이터 조회 불가 |
| 병동 간호사 (`WARD_MEMBER`) | 자신이 속한 병동의 **확정·공개된** 전체 근무표와 본인 근무표 조회. 초안·관리자용 부재 목록 조회 불가 |
| 병동 관리자 (`WARD_ADMIN`) | 초대 생성·철회, 병동 구성원/권한 관리, 근무 유형·필요 인원·확정된 불가 일정 입력, 자동·수동 배치, 초안 검토, 확정·공개 |

- 초대는 병동, 초대할 역할, 필요하면 연결할 가상 간호사 기록을 지정한다. 충분히 긴 무작위 토큰을 사용하고 만료·1회 사용·철회를 지원한다. 서버에는 토큰 원문 대신 해시를 저장한다.
- Kakao 인증을 마친 사용자가 초대를 수락하면 사용자·병동 소속과 해당 간호사 연결을 **한 트랜잭션에서** 생성하거나 기존 가상 기록에 연결한다. 같은 초대나 동일 간호사 연결의 중복을 거부한다. 사용자가 자기 역할을 선택하거나 승격할 수 없다.
- 시연용 첫 관리자는 별도 초기 설정 절차로 만든다. 공개 회원가입만으로 관리자 권한을 받지 않는다.
- 권한은 로그인 토큰의 주장만 믿지 않고 서버의 병동 소속 기록으로 다시 확인한다. 권한 변경과 초대 수락은 감사 기록을 남긴다.

## 근무 불가 정보와 편성 규칙

1. 관리자가 사전에 취합·확정된 휴가와 오전/오후 반차 시간 구간을 등록한다. 이번 MVP에서 간호사 본인이 일정을 신청·결재하거나 곧바로 필수 금지 규칙으로 등록하지 않는다.
2. 배치 후보 조회, 수동 저장, 자동 생성, 최종 확정은 모두 서버의 같은 필수 규칙 검증을 거친다. 클라이언트의 초록/빨강 표시는 안내이며 최종 판정은 서버가 한다.
3. 등록된 근무 불가 구간과 실제 근무 시간이 겹치면 배치하지 않는다. 예를 들어 오후 반차 시간과 Evening 근무가 겹치면 후보에서 불가 사유를 보여준다.
4. 같은 간호사의 근무 시간 중복과 **Night 다음날 Day** 배치를 금지한다. Night 23:00–다음 날 07:00의 날짜 해석과 월 경계를 함께 처리한다. Night 이력은 간호사가 직접 입력하는 불가 일정이 아니라 실제 근무표에서 계산한다.
5. 관리자가 날짜·근무 유형별 필요 인원과 자격 조건을 입력한다. 부족한 경우 규칙을 완화하지 않고 슬롯을 비워 두며 인원과 사유를 보여준다.
6. 균등 배분은 필수 규칙과 충원 다음의 목표다. 시연 MVP에서는 총 근무 수와 Night 횟수의 편차를 보고한다. 최적성이 입증되지 않은 결과를 ‘최적’으로 표시하지 않는다.
7. 자동 생성은 비공개 초안만 변경한다. 이미 공개된 표는 관리자가 새 초안을 검토·확정할 때까지 유지된다. 미충원이 있어도 관리자에게 정확한 부족 수를 보여주고 명시적으로 확인받은 뒤 공개할 수 있다.

## 시연 화면과 공통 흐름

1. 초대 전: Kakao 로그인 → 초대 필요 화면. 관리자는 초대 링크를 만들고 공유한다.
2. 초대 수락: 링크 열기 → Kakao 로그인(필요 시) → 병동/역할 확인 → 소속 생성 → 병동 선택.
3. 관리자: 근무 유형·필요 인원 입력 → 사전 취합된 근무 불가 구간 등록 → 자동 배치 또는 수동 배치 → 가능/불가 사유와 미충원 검토 → 수정 → 확정·공개.
4. 간호사: 공개된 병동 전체/내 근무 전환 → 날짜별 근무자 확인. 비공개 사유·초안은 보이지 않는다.
5. Android와 웹은 같은 병동·월·revision을 표시한다. 한쪽에서 확정한 뒤 다른 쪽이 새로 조회하면 같은 공개본이 나온다.

## 시연 인수 기준

1. 초대받지 않은 Kakao 계정은 병동 근무표와 개인정보를 조회할 수 없다. 초대는 만료·재사용·다른 병동 사용이 차단된다.
2. 초대 수락 후 사용자·병동 소속·간호사 연결이 중복 없이 생성되고, 역할 변경은 관리자만 가능하다.
3. 관리자가 근무 유형·필요 인원·확정된 불가 구간을 입력한 뒤 월간 초안을 생성할 수 있다.
4. 휴가/반차 시간 중복, 같은 간호사 근무 중복, 전날 Night→다음날 Day는 **후보 안내뿐 아니라 서버의 모든 저장·생성·확정 경로에서 0건**이다. 월 경계도 포함한다.
5. 채울 수 없는 칸은 미충원 수와 이유가 보이고, 자동 생성이 필수 규칙을 임의로 어기지 않는다.
6. 관리자 확정 전 초안은 간호사 API·Android·웹에서 보이지 않는다. 미충원 공개는 관리자가 정확한 부족량을 확인한 경우에만 가능하다.
7. 확정 후 Android와 웹에서 병동 전체와 본인 보기가 동일한 활성 revision을 읽는다. 다른 병동 사용자는 접근할 수 없다.
8. 두 관리자의 동시 편집과 중복 실행은 revision·멱등성 검사로 안전하게 처리된다.
9. 가상 데이터의 **완전 충원 가능 사례와 미충원 사례**를 각각 시연한다. 실제 병원 생산성 50% 개선은 시연 성공 주장에 포함하지 않는다.

## 이번 MVP에서 제외

- 간호사 본인의 휴가·반차 신청/결재 또는 근무 불가 직접 등록, 근무 선호 입력
- 급여·근태·출퇴근, 법정 연차 계산, 환자 정보·진단·휴가 사유 수집
- 생성형 AI가 필수 규칙을 판단하거나 자동 확정·공개하는 기능
- 실제 병원 직원 데이터, 폐쇄망 단일 PC 모드, Cloudflare D1/Workers DB 전환
- 엑셀 가져오기, 통계 그래프, 광고·과금, 제조업 등 타 업종 확장

## 현재 코드와 남은 구현

- `backend/`에는 H2 기반 초안·근무 불가·수동 배치·확정·공개와 초기 규칙 기반 생성 코드가 있다. Kakao 로그인/초대/권한 관리, 직원·근무 유형 관리 API, 운영 DB 이전은 아직 연결되지 않았다.
- `android/`는 Figma 기반 시연 화면과 가상 데이터를 로컬에서 표시한다. 서버 로그인·초대·API 연동 전에는 공유 근무표가 아니다.
- 웹 클라이언트는 새로 만들어야 한다. Android·웹 모두 인증/초대, 공통 API, 오류·revision 처리를 연결해야 한다.
- [OpenAPI 초안](openapi.yaml)에 Kakao 세션·초대 수락·권한 관리 계약을 추가하고, 구현과 응답 형식의 차이를 검증해야 한다. 지금의 OpenAPI는 이 신규 인증/초대 흐름에 대해 구현 준비가 끝난 계약이 아니다.

### API 계약에 추가할 흐름

| 요청 | 목적과 필수 조건 |
| --- | --- |
| Kakao OIDC 로그인 시작/콜백 또는 앱 코드 교환 | Android·웹의 로그인 결과를 서버 세션/API 토큰으로 연결. 실제 Kakao 앱 등록과 Redirect URI를 정한 뒤 경로·토큰 저장 방식을 확정 |
| `POST /api/v1/wards/{wardId}/invitations` | 관리자만 역할과 기존/신규 간호사 연결 대상을 지정해 만료되는 1회 초대 생성 |
| `POST /api/v1/invitations/redeem` | Kakao 로그인 사용자만 초대 코드를 제출. 코드 소진·사용자·병동 소속·간호사 연결을 원자적으로 처리 |
| `DELETE /api/v1/wards/{wardId}/invitations/{invitationId}` | 관리자의 미사용 초대 철회 |
| `PATCH /api/v1/wards/{wardId}/memberships/{userId}` | 관리자 권한 재할당·비활성화. 자기 권한 승격 금지와 감사 기록 필수 |
| 기존 `GET /api/v1/me`, `GET /api/v1/wards` | 로그인 후 본인과 초대 수락으로 생긴 병동 소속만 반환 |
