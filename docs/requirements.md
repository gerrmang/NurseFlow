# PRD: 병동 간호사 근무표 관리 및 자동 편성

## 상태와 목표
개발 전 요구사항 문서. 기반 명세: [Deep Interview spec](requirements-interview.md). Greenfield 프로젝트다. 앱 클라이언트는 Kotlin 사용을 선호하며 Android 네이티브 앱을 우선 가정한다. Android 타깃과 서버/저장소 구조는 P0에서 확정한다.

관리자가 엑셀에서 여러 간호사의 일정과 규칙을 일일이 대조하는 시간을 줄인다. 시스템은 규칙 기반으로 월간 근무표 초안을 자동 작성하고, 관리자가 검토·수정·확정·공개한다. 핵심 성공 목표는 월간 전체 편성 작업시간이 기존 엑셀 대비 절반 이하가 되는 것이다. 기준 시간은 모르는 상태이므로 파일럿에서 먼저 측정한다. 안전 규칙 위반이나 검토 누락으로 단축한 시간은 성공으로 보지 않는다.

## 기술 방향(현재 선호)
- 앱 클라이언트는 Kotlin으로 개발한다. 현재는 Android 네이티브 클라이언트라는 가정으로 기획한다.
- 여러 관리자와 간호사가 같은 공개 근무표를 공유해야 하므로 서버 API와 중앙 데이터 저장이 필요할 가능성이 높다. 다만 서버 언어, API 방식, DB, 호스팅은 미결정이다.
- 앱이 오프라인에서도 편성/조회되어야 하는지, 실시간 동기화/푸시 알림이 필요한지는 P0에서 결정한다.
- Kotlin/Android 선택은 제품 요구사항의 hard rule, 검증, 승인·공개 경계를 바꾸지 않는다.

## 사용자와 권한
- 관리자(수간호사 등): 인력·근무 수요·정책·승인된 휴가/반차 입력, 자동/수동 편성, 초안 검토·수정·확정. 확정 시 새 revision이 활성 달력에 공개 적용된다.
- 간호사: 공개된 근무표 조회만. 신청·결재·편집은 범위 밖.
- 간호사는 병동 전체 달력 보기와 본인 일정 보기 사이를 전환할 수 있다. API별 접근 권한을 서버에서 확인한다.

## 사용자 흐름
1. 관리자가 월과 근무 유형/실제 시작·종료 시간/필요 인원 및 규칙을 설정한다.
2. 관리자가 이미 승인된 휴가·반차를 시간 구간으로 등록한다. 휴가 사유나 진단 정보는 받지 않는다.
3. 자동 초안 생성 또는 수동 배치 수행.
4. 같은 규칙 검증기가 배치 가능 여부, 규칙 코드, 설명을 표시한다.
5. 자동 배치는 hard rule을 지키고 미충원과 상태를 구분한다.
6. 관리자가 초안과 공정성·미충원 요약을 검토하고 수정한다.
7. 서버가 최신 정책/일정 버전으로 재검증한다.
8. 관리자가 최종 확인/확정하면 서버가 최신 규칙으로 재검증하고 그 revision을 원자적으로 공개해 활성 달력에 적용한다. 미충원이 있어도 관리자가 확인한 뒤 확정할 수 있다.
9. 이후 변경은 새 draft에서 검토·수정한 뒤 다시 확정하며, 초안은 간호사 달력에 보이지 않는다.

## MVP 요구사항
- 월별 달력에 근무 유형, 필요/배치/미충원 인원을 표시.
- 실제 시간 구간으로 근무, 승인된 전일 휴가, 반차 등록.
- 수동 배치 시 날짜·시간별 가능/불가와 이유를 즉시 제공.
- 정해진 hard rule 기반 월간 자동 초안 생성.
- 균등 배분을 soft objective로 최적화하고 미달 이유를 설명.
- 채울 수 없는 슬롯을 빈 채로 두고 미충원 수와 이유를 표시.
- 자동 생성은 확정 또는 게시하지 않는다.
- 관리자는 초안을 수정하고 확정한다. 확정된 revision은 공개되어 달력에 적용되며, 간호사는 병동 전체/본인 보기를 선택한다.
- 서버 측 병원/병동 권한 검사, 비공개 부재정보 분리.

### Hard constraints
- 지정 휴가와 근무 구간 겹침 금지.
- 반차와 근무 구간 겹침 금지(예: 오후 반차는 오후근무 배정 불가).
- 나이트 다음날 데이 배정 금지; 정확한 최소 휴식시간 및 경계 시각은 P0에서 정의.
- P0에서 합의한 기타 필수 병동 정책.
- 불가 시 빈 슬롯을 유지한다. 자동 완화나 예외 위반 금지.

### Soft objectives
- 근무 수/시간/야간/주말 배분 등 운영자가 확정한 공정성 지표를 개선.
- 적격 인원·분모·가용시간 보정은 P0에서 정한다.
- hard rule 준수 → 미충원 최소화 → fairness 개선 순서를 기본안으로 검토한다.
- “최적”은 최적성이 증명된 경우에만 표시. timeout은 불가능 증명이 아니다.

## 결과 상태 구분
- 개별 배치 거부: 이름 있는 규칙과 원인을 설명.
- 초안 미충원: 요구 인원과 부족량 표시.
- timeout/취소/엔진 오류: 완료 여부/불가능 여부 미확정.
- 증명된 infeasible: 솔버가 증명할 수 있을 때만 별도 표시.
휴리스틱 실패나 제한시간 종료로 “유효한 근무표가 없다”고 단정하지 않는다.

## 자동배치 해석
사용자가 요청한 “AI 기반 자동배치”는 먼저 hard constraint를 명시적으로 보장하고 균등 배분 같은 soft objective를 최적화하는 일정 최적화 문제로 다룬다. 생성형 AI/LLM이 근무 규칙을 임의로 해석하거나 예외를 승인하지 않는다. P0에서 결정적 휴리스틱과 제약 최적화 엔진을 같은 조건으로 비교해 구현 방식을 확정한다.

## 비목표
급여·근태·출퇴근, 휴가/반차 신청 및 결재, 법정 연차 잔여일수 계산, 공식 HR 대체, 관리자 승인 없는 자동 게시, hard rule 완화, 의료·진단/휴가 사유 수집.

## 인수 기준
1. 자동 생성·수동 편집·확정·공개 모든 쓰기 경로에서 확정된 hard rule 위반은 0건.
2. 위반 배치는 UI뿐 아니라 API에서도 원자적으로 거부되며 규칙 설명을 반환.
3. 미충원량, 배치 거부, timeout/취소/오류, 증명된 불가능 상태를 구별.
4. 검토 전 초안은 URL/API/export에서도 간호사에게 보이지 않는다.
5. 타 병동 사용자와 간호사는 비공개 부재정보 및 비허용 범위 데이터에 접근할 수 없다.
6. 관리자의 confirm 요청 성공 시 새 revision이 활성 달력에 공개 적용된다. 미충원 표는 부족 슬롯 수를 보여주고 명시 확인을 받아 확정할 수 있다. 초안은 보이지 않고 오래된 revision은 최신 표를 덮지 않는다.
7. fairness 계산이 고정 fixture에서 재현되며, 증명 전 결과는 ‘최적’으로 표시되지 않는다.
8. 파일럿 비교에서 사전에 합의한 표본 조건을 충족하고 전체 월간 작성 시간이 엑셀 기준의 50% 이하. 기준선은 파일럿 전 기록하며 교육/최초 설정 시간은 별도 보고.

## P0에서 반드시 정할 항목
병동/직원/관리자 규모, Android 타깃 OS와 UI 방식, 타깃 국가 및 배포·인증·데이터 위치, 서버/API/DB와 동기화·오프라인 요구, 근무별 실제 시간과 시간대, 수요 인원 및 숙련도 조건, 나이트 후 휴식의 시간 의미, 월 경계 데이터, 추가 hard rules, fairness 산식·대상·분모, 기존 고정 배치 유지 여부, 병동 전체/본인 API에 대한 서버 membership 검증, 공개본 이력/보존/삭제, 동시성 및 성능 한도, 엑셀 import/export, 비교 파일럿 표본 수와 시간 계산 정의.

## 보안 및 개인정보 고려
시간 구간과 필요한 최소 분류만 저장하며 병가·진단 사유는 받지 않는다. 관리자/간호사 역할과 병원/병동 membership은 서버에서 검사한다. 관리자 사유 필드는 간호사 화면에서 분리한다. 보존·삭제·백업·감사 정책은 배포 위치와 병원 요구사항 확인 후 결정한다. 법령·현장 정책 검토 없이 법적 적합성을 보장한다고 표시하지 않는다.
