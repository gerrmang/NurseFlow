# Test Specification: 간호사 근무표 앱

초기 시연은 [MVP 범위](mvp-scope.md)와 [월간 편성 규칙](monthly-roster-rules-and-two-person-plan.md)을 따른다. 아래 파일럿 시간 목표는 실제 병원 도입 평가에만 적용한다.

## 품질 게이트
1. 채택된 hard rule 위반 0건: 자동·수동·확정·공개 모두 검증.
2. 미충원, 특정 규칙 거부, timeout/실패, 증명된 infeasible을 혼동하지 않음.
3. 초안·부재정보·타 병동 정보에 대한 권한 우회 0건.
4. 관리자의 확정 전에는 draft가 숨겨지고, 확정 성공 시 publication이 원자적으로 적용됨.
5. 초대받지 않은 Kakao 로그인 사용자와 다른 병동 사용자의 데이터 접근 0건.
6. Android와 웹이 확정 후 같은 활성 공개 revision을 조회.
7. 비교 가능한 **후속 파일럿**에서 전체 월간 작업시간 <= 엑셀 기준 50%.
8. 팀별 경력 구성 최적화가 hard rule·필요 인원 충원보다 우선하지 않으며, 미달 사유와 실제 단계 분포가 관리자에게 재현 가능하게 표시됨.
9. 팀 간 지원근무는 관리자 허용 범위 밖에서 자동·수동·확정 모두 0건이고, 허용된 배치는 실제 배치 팀의 충원·경력 구성에만 계산됨.
10. 초대 수락한 활성 간호사만 편성하고 관리자 계정은 제외. 확정표에서 연속근무 5일 초과, 일반 직원 월 Night 6회 이상 SOF 누락, 병동 설정 선임 최소 인원 위반, 일반 직원 월 목표 환산시간 부족 0건.

## P0 정책 계약 (모든 fixture에 버전 기록)
병원/병동·소속 팀·실제 배치 팀·timezone, 월간 시간 범위 및 인접 월 조건, 실제 근무 시작/종료·환산시간, 병원 휴일 달력·목표시간, 초대 수락/활성 직원 모수, 일반/Day·Evening/Night 전담 근무 형태와 3개월 순환, SOF·연속근무·희망 오프 정책, 직원 자격/팀별 수요·선임 최소 인원, 관리자 팀 간 지원근무 허용 범위·철회·버전, 병동 관리자가 설정한 근무연차·직급의 1~5단계 변환 정책 버전과 프로필 확인 상태, 휴가·반차 interval 경계, hard/soft 정책과 버전, 경력 구성·fairness 산식/적격집단/분모, 기존 고정배치 처리, 미충원 확인/공개 정책, 생성 시간제한·status, 권한·공개 범위.

## Golden fixtures
- 전일 휴가, 오전/오후 반차; 근무와 정확히 맞닿거나 겹치는 interval.
- 자정 넘는 나이트 및 휴식시간 임계값.
- 전월 말 나이트→당월 1일 데이, 당월 말 나이트→익월 데이.
- 휴가/자격/필요인력 충돌로 인한 shortage.
- 가용 시간·계약량·야간 자격이 다른 직원의 fairness 비교.
- 같은 병동 A/B팀의 경력 단계 1~5, 근무별 필요 인원 2·3·5명, 한 단계 인원 부족, 휴가·반차·Night 휴식으로 특정 단계가 불가한 경우. 단계 다양성 목표가 충원·hard rule과 충돌하면 미충원과 경력 구성 미달을 구분한다.
- 간호사가 입력한 근무연차·직급이 관리자 확인 전이거나 확인 후 수정된 경우, 병동 단계 기준이 변경된 경우. 미확인 입력이 경력 구성 점수에 들어가지 않고 관리자에게 표시되는지 확인한다.
- A팀 간호사의 B팀 지원근무: 허용 전 거부, 관리자가 범위를 지정한 뒤 허용, 범위 밖 날짜·근무/다른 팀 거부, 허용 철회 후 초안 확정 거부, B팀 충원·단계 분포에 반영.
- hard rules와 soft goals가 상충하는 사례.
- 알려진 feasible/infeasible 작은 모델 및 솔버 timeout.
- 재생성 시 고정 배치, 정책 변경, 생성 중 최신 데이터 변경.
- 다중 관리자 동시 편집·확정·중복 공개.
- draft/confirmed/published 및 다른 병동 권한.
- 초대 만료·1회 사용·철회·중복 수락·다른 병동 사용·간호사 연결 중복.
- 초대 수락 전/후, 관리자 계정, 비활성 직원의 편성 모수 차이. 팀 개수 2·4개, 팀별 인원 부족, 병원별 Day/Eve/Night 시작 시각 차이.
- 30일·기준 휴식일 9일·하루 8시간의 목표 168시간, 겹치는 주말/공휴일 중복 제거, D/E 7.5·N 9·VY/SOF 8의 예시 환산, Night 전담 별도 목표와 음수 잔여시간 충돌.
- 일반 간호사 N 5/6/12회의 SOF 0/1/1일과 같은 달 내 자유로운 SOF 날짜, 전담자의 별도 SOF 정책. 전담 2명씩 3개월 블록 교체, 월 N 14/15회 경계, Day/Evening 전담의 N 금지.
- 31일 달에 전담 2명 × 최소 Night 15회로는 Night 31칸 전체를 채웠다고 가정할 수 없는 사례. 일반 3교대 인력의 추가 배치 또는 미충원 진단을 확인.
- 월 경계에 걸친 5일 연속근무 후 6일째 `OF`/`SOF`, 중간 `VY`는 근무일도 휴식 리셋일도 아닌 상태. 간호사·관리자 양쪽 입력 희망 오프와 미반영 사유, 선임 0명인 팀 근무의 미충원.

## Unit/property tests
- interval overlap, boundary, overnight, timezone, 월말·월초.
- 동일 validator의 rule code/설명 및 hard-before-soft 우선.
- 소속 팀과 배치 팀이 다를 때 관리자 허용 범위 판정, 종료 경계, 허용 철회와 중복 근무 검사.
- fairness 산식 및 적격집합의 결정성.
- 근무연차·직급의 단계 계산 경계값과 팀별 경력 분포 점수의 결정성. 5명 미만 근무에 1~5단계 전원 배치를 강제하지 않는지 확인.
- 병동별 연차·직급 정책이 다를 때 같은 입력의 단계 계산, 정책 변경 후 재계산·초안 재검증, 확인되지 않은 프로필의 점수 제외.
- 병원별 시각 구간과 환산시간을 다른 값으로 변경해 실제 근무시간·목표시간이 독립적으로 계산되는지 확인. 월 목표일수는 주말·공휴일의 합집합으로 계산.
- 일반 직원 SOF 임계값과 월 1일 상한, 전담 3개월 블록·월 N 최소 횟수, 연속근무 5일 상한과 `VY` 별도 처리, 팀별 선임 최소 인원 판정을 각각 경계값으로 확인.
- 빈/중복/누락 일정 입력 처리.
- 모든 생성 결과는 독립 validator 통과 또는 폐기/오류 상태.
- 작은 모델은 exhaustive oracle로 feasible/optimality/infeasible status 확인.
- timeout/취소/엔진오류를 불가능으로 분류하지 않는지 확인.

## Integration tests
- solver/heuristic 결과 → 독립 검증 → draft 저장.
- validator가 수동 저장, 확정, 공개에 모두 적용.
- 변경된 policy/leave/staff revision이 stale 초안을 무효화.
- 거부 시 수정은 원자적으로 반영되지 않으며 설명 제공.
- shortage 상태, 생성 status, 이유가 API/UI에서 일치.
- 동일 날짜·근무의 팀별 경력 구성 진단이 자동·수동 편성 결과와 일치하며, 단계 미달만으로 배치·확정을 거부하지 않음.
- 팀 간 지원근무 허용 변경이 stale 초안을 재검증하게 하고 후보·수동 저장·자동 생성·확정이 같은 서버 판정을 사용함.
- 희망 오프의 직접·대리 입력 권한과 출처, Night 전담/시간/SOF/선임 정책 수정 시 초안 재검증, 월 목표 미달·초과·미충원 진단을 API와 화면에서 일치시킴.
- 공개 스냅샷 및 재공개 revision 관리.
- 서버에서 role·hospital·ward membership 확인; URL/object ID 변조 테스트.
- Kakao 로그인만 완료한 사용자는 병동 조회 거부; 초대 수락으로 사용자·membership·간호사 연결을 원자적으로 생성. 자기 권한 승격과 초대 재사용 거부.
- logs/export/errors에 사유·건강정보·타 병동 데이터가 남지 않는지 확인.
- 간호사의 근무연차·직급 입력은 본인 프로필만 수정할 수 있고 관리자 확인 권한은 병동 관리자에게만 있다. 간호사 공개 근무표 응답에 개인 경력 프로필·확인 기록이 섞이지 않는지 확인.

## E2E
1. 관리자가 병동 초대 링크를 발급하고, Kakao 로그인 사용자가 수락해 소속·역할을 얻는다. 초대 전에는 병동 자료가 보이지 않는다.
2. 관리자가 병원 시간·환산·휴일·SOF 정책과 팀·선임·Night 전담을 설정하고, 간호사/관리자가 희망 오프를 입력한 뒤 자동 초안을 생성.
3. 불가/미충원/팀별 경력 구성/fairness 이유 확인, 관리자 허용형 팀 간 지원근무와 수동 수정 후 재검증.
4. draft는 간호사에게 숨기고, manager confirm 성공 시 활성 달력으로 공개. 기존 public revision은 새 draft 생성 중 그대로 노출.
5. 필요 인원으로 생성된 근무 칸이 없는 초안은 확정 불가. 미충원 표는 확정 가능하며 부족 슬롯/인원을 관리자가 확인했다는 기록을 남기고, hard rule 위반은 계속 차단.
6. 게시 후 변경은 새 revision으로 진행, stale 변경은 덮어쓰지 않음.
7. 타 병동/비인가 사용자 API 조회 및 export가 거부됨.
8. 생성 timeout/cancel/retry가 현재 유효한 초안을 덮지 않고 정확한 상태 노출.
9. Android와 웹의 병동 전체/내 근무 화면이 동일한 공개 revision을 사용. 관리자가 한쪽에서 확정한 결과를 다른 쪽에서 조회 가능.

## Android·웹 클라이언트 검증
- 도메인/화면 상태 로직은 Kotlin 단위 테스트로 규칙 결과와 화면 상태 변환을 검증한다.
- Android UI/E2E에서 관리자 달력 편성, 자동초안 검토, 확정/공개, 간호사 읽기 화면과 권한 상태를 확인한다.
- 웹 UI/E2E에서도 같은 역할·초대·편성·확정·조회 흐름과 오류/revision 상태를 확인한다.
- 다양한 화면 크기, 시스템 글자 크기, 키보드/스크린리더, 색상 이외의 가능/불가 표시를 확인한다.
- 두 클라이언트의 응답 모델은 같은 OpenAPI 계약과 서버 통합 테스트로 검증한다.

## 성능·관측
P0에서 최대 직원·월 슬롯·동시 관리자 규모와 SLO를 고정한 뒤 측정한다. duration, termination state, shortage count, validation failure type, input/policy/engine revision을 기록한다. telemetry에 이름, leave reason, 건강정보는 포함하지 않는다. cancel·retry·backup/restore의 일관성도 검증한다.

## 파일럿 시간 측정 프로토콜
- 엑셀과 앱의 동일한 작업범위를 정하고, 시작(데이터 준비 시작)부터 관리자 확정(활성 달력 적용)까지 시간을 기록.
- 준비·입력·생성 대기·검토·수정·재생성·확정/활성화 포함.
- 교육/최초 데이터 정리 시간은 분리 보고.
- 월 규모/정책 복잡도/수요/미충원/중단을 기록해 비교가능성 판단.
- 최소 월/관리자 관측수와 중앙값 등 통계 정의를 파일럿 전에 고정.
- 목표 <= 기준 시간 50%와 동시에 hard-rule/권한/게시 게이트를 통과해야 성공.

## 요구사항 연결
휴가/반차/야간 휴식 -> boundary fixtures; 팀별 경력 구성 -> 단계 계산·분포 fixture; fairness -> fairness oracle; 미충원/진단 상태 -> shortage+timeout cases; 관리자 공개 -> lifecycle E2E; 개인정보/권한 -> API/export/log tests; 시간 목표 -> pilot protocol.
