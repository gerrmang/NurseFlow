# 월간 3교대 자동편성 규칙과 2인 개발 분담

상태: 2026-10-31 요구사항 정리. 이 문서는 [초기 MVP 범위](mvp-scope.md)를 확장하는 설계 입력이다. 병원별 수치와 코드의 의미는 관리자 설정으로 모델링한다. **현재 코드에 아래 기능이 구현되었다는 뜻은 아니다.** 실제 간호사 이름·근무 이력과 원본 엑셀은 저장소에 넣지 않는다.

## 예시 엑셀에서 확인한 것

사용자가 제공한 월별 근무표 19개 시트를 읽기 전용으로 확인했다. 날짜별 D/E/N 및 `OF`, `VY`, `SOF` 등의 코드와 개인별 횟수·시간·잔여시간 집계가 있다. 한 시트의 시간 계산 예시는 D/E 7.5시간, N 9시간, VY/SOF 8시간을 반영한다. 최근 여러 시트에서 일반 근무자에게 N 6회와 SOF 1일, Night 전담으로 보이는 행에 N 15회와 SOF 0일이 관찰되었다. 일부 전담 행의 잔여시간은 음수다. **이 수치는 예시 파일의 계산 결과이며 병원 공통 규칙이나 새 앱의 정답으로 복사하지 않는다.** `DE`, `DD`, `ET`, `DK`, `VV`, `VS` 등 다른 코드의 뜻은 확인 전까지 추정하지 않는다.

## 날짜·근무 코드와 월 목표시간

1. `VY`는 승인된 연차 일정이다. 기존 MVP의 관리자 입력 승인 부재 흐름에 연결한다. `OF`는 오프, `SOF`는 Night 기준 충족 시 부여되는 sleeping off로 모델링한다. 희망 오프는 연차 승인과 별도 입력이다. 나머지 엑셀 코드는 확인되기 전까지 자동 변환하지 않는다.
2. 병원별 근무 코드·근무 유형의 **실제 시작/종료 시각**과 **월간 환산시간**을 각각 저장한다. 예시 엑셀의 D/E 7.5, N 9, VY/SOF 8은 이 병원의 시연 설정 후보일 뿐이다.
3. 병원이 정한 달력에서 해당 월의 주말과 공휴일을 중복 없이 세어 기준 휴식일을 계산한다. 기본 계산안은 `목표일수 = 월 일수 - 기준 휴식일수`, `월 목표 환산시간 = 목표일수 × 기준 1일 시간`이다. 사용자의 예시는 `30 - 9 = 21일`, `21 × 8 = 168시간`이다. 병원별 달력·기준 시간·대체휴일 반영 방법은 정책 버전으로 기록한다.
4. `실제 근무시간`은 배정된 근무의 시각 구간 합계, `월간 환산시간`은 병원별 환산 정책에 따른 D/E/N과 VY/SOF 등의 합계로 분리해 표시한다. `잔여시간 = 월간 환산시간 - 개인별 목표시간`으로 계산한다. VY·SOF와 근무 유형별 환산시간은 **병원별 설정**이고 엑셀의 7.5/9/8시간은 시연 예시로만 사용한다.
5. 일반 간호사는 월 목표시간 미달을 확정 단계에서 허용하지 않는다. 초안에서는 부족 시간을 보이며 근무를 더 배치하거나 정책·대상 인원을 조정한다. 목표 초과는 허용하되 초과시간을 별도로 표시한다. 휴가·휴식·연속근무 등 필수 규칙을 깨서 시간을 채우지 않는다. Night 전담은 **별도의 월 목표시간과 Night 환산시간**을 설정한다.

## 자동배치 규칙의 우선순위

| 우선순위 | 규칙 | 처리 |
| --- | --- | --- |
| 1. 필수 | 승인 휴가·반차와 실제 근무시간의 중복, 한 간호사의 근무 중복, Night 다음날 Day, 허용하지 않은 근무 유형, 관리자가 허용하지 않은 팀 간 배치, 연속근무 상한 | 후보·수동 저장·자동 생성·확정에서 동일한 서버 판정. 위반을 임의로 풀지 않는다. |
| 2. 필요 인원·선임 | 팀·날짜·근무별 인원과 지정된 자격, 병동 정책에 따른 선임 최소 인원 | 선임이 없으면 선임 필요 칸을 미충원으로 표시한다. 주니어로 선임 자리를 메우지 않는다. 기존 미충원 공개 정책과 월 목표시간 조건의 결합은 설계 단계에서 검증한다. |
| 3. 월 목표 | 개인별 월 환산시간이 목표에 도달하도록 한다. Night 전담은 별도 환산·목표 정책을 적용한다. | 목표 미달·초과를 각각 표시한다. 불가능하면 원인을 반환하고 자동 확정하지 않는다. |
| 4. 선호·품질 | 희망 오프 반영, 팀·근무별 1~5 경력 단계 분산, 개인별 Day/Eve/Night·주말 부담 균형 | 가능한 한 개선한다. 달성하지 못하면 희망 오프 미반영·경력 구성 미달을 구분해 관리자에게 설명한다. |

### Night와 연속근무

- 일반 간호사는 한 달의 Night가 **6회 이상이면 SOF 1일**을 부여한다. 같은 달에 Night가 12회 이상이어도 SOF를 자동으로 추가하지 않는다. SOF는 같은 달 안의 어느 날짜에나 배치할 수 있으며 Night 블록 직후로 고정하지 않는다. 임계값·SOF 환산시간은 병원별 정책으로 설정한다. Night 전담자는 이 일반 규칙에서 제외하고 병원별 **전담 휴식 정책**을 적용한다.
- Night 전담은 동시에 **2명**을 지정해 **연속 3개월** Night만 근무한 뒤 다른 2명과 교대한다. 전담 기간의 월 Night는 **최소 15회**다. 병원 정책으로 전담 인원·주기·최소 횟수·개인 목표/환산시간을 변경할 수 있다. Day/Evening 전담은 N을 배정하지 않는다. 순환 종료·월 경계·휴가·중도 입퇴사를 처리한다.
- 연속근무는 **최대 5일**로 월 경계를 넘어 센다. 5일 근무했다면 6일째는 `OF` 또는 `SOF`가 필요하다. `VY`는 근무일로 세지 않지만 연속근무를 끊는 오프로도 세지 않는다. 따라서 VY 전후의 근무 연속성은 별도로 이어서 검사한다.
- 희망 오프는 간호사가 직접 제출하거나 관리자가 대신 입력할 수 있고, 입력 주체를 기록한다. 승인 연차와는 별개이며 가능한 한 반영하는 선호 목표다. 충원과 충돌하면 미반영 사유를 표시하고, 제출·수정 마감 시각은 병동 정책으로 정한다.

### 팀과 경력 구성

- 팀 개수는 고정 4개가 아니다. 병동 관리자가 설정한 팀과 편성 가능한 간호사 수로 팀별 수요를 만든다.
- 각 팀의 한 Day/Eve/Night 근무에 경력 단계가 한쪽으로 몰리지 않도록 한다. 한 근무의 필요 인원이 5명 미만일 때 1~5단계를 모두 요구하지 않는다. 실제 배치 팀 기준으로 단계 분포·미달 사유를 보여준다.
- 병동 관리자가 선임으로 인정할 단계(예: 4·5)와 팀·근무별 최소 인원을 설정한다. 설정된 선임 최소 인원은 **필수 조건**이다. 충족할 수 없으면 선임 필요 칸을 미충원으로 표시하고 이유를 제시한다. 전체 경력 단계의 고른 분포는 그 다음의 선호 목표다.

## 생성·검토 화면에 필요한 결과

- 생성 전: 팀별 필요 인원, 편성 가능 인원, 경력 단계·근무 형태·확정 부재·희망 오프·팀 간 지원 허용, 개인별 월 목표시간과 Night 전담 기간을 검토한다.
- 생성 중: 정책 버전·입력 revision을 고정하고 작업 상태·취소·시간 제한을 표시한다.
- 생성 후: 근무 칸별 가능/불가 사유, 팀·경력 단계 분포, 선임 충족 여부, Night/SOF 횟수, 최대 연속근무, 희망 오프 반영률, 개인별 실제/환산/목표/잔여/초과시간, 미충원을 보여준다.
- 관리자는 초안을 수정한 뒤 서버 재검증을 거쳐 확정한다. 확정 전에는 간호사 공개 달력이 변하지 않는다. 충돌하는 정책이 있으면 ‘불가능한 규칙 조합’을 구체적으로 표시하고 자동으로 규칙을 완화하지 않는다.

## 현재 코드와의 차이

현재 백엔드는 `wards`, `nurses`, `shift_types`, `rosters`, `roster_slots`, `approved_absences`를 갖고 있으나 병원·팀·편성 가능한 초대 간호사 모수, 근무 형태·Night 전담 순환, SOF·희망 오프, 휴일 달력·월 목표/환산시간, 선임 필요 칸을 저장하지 않는다. `shift_types.kind`도 `DAY`, `NIGHT`, `OTHER`여서 Evening을 별도 근무 유형으로 계약화해야 한다. 기존 생성기는 새 정책을 고려하지 않으므로 이 문서만으로 자동배치가 바뀌지 않는다. 패키지 구조 정리와 기존 회귀 테스트를 먼저 마친 뒤 기능별 DB/API 변경을 한다.

## 2인 개발 분담

두 개발자는 **기능 단위로 작은 `dev` PR**을 만든다. 현재 별도 작업 폴더에서 진행 중인 패키지 구조 정리를 먼저 검증하고 PR로 병합한다. 이후 아래 작업은 계약을 먼저 고정하고 서로 다른 작업 폴더에서 병행한다. 같은 파일은 동시에 수정하지 않는다.

| 순서 | 개발자 A: 서버·편성 엔진 (`backend/`) | 개발자 B: Android·웹·E2E (`android/`, `web/`) | 합류 기준 |
| --- | --- | --- | --- |
| 0 | 기존 서버 규칙·DB와 신규 정책 차이를 정리하고 OpenAPI 초안을 작성한다. | Figma·엑셀의 관리자 입력/검토 화면 요구를 정리하고 API 응답을 검토한다. | 정책표, 테스트 사례, DTO 이름·오류 코드 합의. |
| 1 | 초대 수락·활성 직원·팀/경력/근무 형태 데이터와 관리자 정책 API를 기능별 PR로 구현한다. | 로그인·초대·프로필·팀 설정 화면을 목업 API로 구현한다. | 실제 API 계약과 화면 모델이 일치. |
| 2 | 병원별 근무 시각·환산시간·휴일 달력·월 목표시간, VY/SOF·희망 오프·Night 전담 정책을 각각 검증 가능한 PR로 구현한다. | 부재·희망 오프·Night 전담·월 목표시간 입력/조회 화면을 만든다. | 정책 경계값·월 경계·권한 테스트 통과. |
| 3 | 팀별 필요 인원, 허용형 팀 간 지원, 자격·선임·연속근무·Night 제한의 서버 판정과 자동배치를 구현한다. | 수동 배치 후보, 자동배치 진행, 불가/미충원/시간 부족 진단 화면을 연결한다. | 후보·수동·자동·확정이 동일 규칙을 사용. |
| 4 | 경력 분산·희망 오프·근무 균형 목표를 개선하고 검증 결과를 공개 API에 반영한다. | Android·웹에서 병동 전체/본인 공개표와 관리자 검토·확정 E2E를 검증한다. | 동일 공개 revision, 개인별 시간/경력 진단, 회귀 CI 통과. |

`docs/openapi.yaml`은 개발자 A가 수정하고 개발자 B가 소비자 관점에서 검토한다. 공통 정책 문서는 한 PR에서 한 사람만 수정한다. 개발자 B는 서버 준비 전 계약 기반 목업으로 화면을 진행할 수 있지만, 실제 연동 완료를 주장하려면 서버 통합 테스트가 필요하다. 기능별 PR에는 담당자, API/DB 변경, 검증·미검증, 롤백, 남은 위험을 기록한다.

## 구현 순서와 테스트 게이트

1. **정책 결정:** 아래 열린 항목을 정하고 병원 기본값과 병동 예외의 우선순위를 문서·OpenAPI에 기록한다.
2. **데이터·API:** 팀·프로필·근무 유형·부재/희망 오프·Night 전담 순환·휴일 달력·일반/전담 목표시간·팀별 수요/선임 최소 인원의 CRUD와 권한을 작은 PR로 구현한다.
3. **독립 규칙 검증:** 날짜/시간, 월 경계, Night 후 Day, 허용형 팀 간 지원, 연속근무, SOF, 월 목표시간과 선임 최소 기준을 각각 단위·통합 테스트로 검증한다.
4. **자동배치:** 먼저 필수 규칙과 충원, 다음 월 목표, 마지막 희망 오프·경력 분산·균형을 다룬다. 조건을 만족하지 못하면 원인과 미달량을 반환한다.
5. **클라이언트·공개:** Android와 웹에서 같은 API/revision과 관리자 확정 경계를 확인한다. 실제 간호사 정보 대신 합성 시연 데이터로 E2E를 실행한다.

## 구현 전에 결정할 항목

- 실제 병원에 적용할 D/E/N/VY/SOF 환산시간, 일반/전담 월 목표시간과 휴식 정책의 구체 값. 예시 엑셀의 숫자는 고정값이 아니다.
- 병동별 선임 단계 기준·팀/근무별 최소 인원, 관리자 대신 입력한 희망 오프의 수정·마감 절차.
- Night 전담 3개월 블록의 시작 기준일, 중도 입퇴사와 교대 인원 부족 시 처리.
- Night 근무가 자정을 넘을 때 월별 Night 횟수와 환산시간을 어느 날짜의 월에 귀속할지.
- 병원 휴일 달력·주말·대체휴일·병동 예외의 입력/버전 관리와 Night의 월 귀속 기준.

구체적인 병원 정책과 예시 엑셀의 관찰값이 충돌하면 사용자에게 확인한 정책이 우선한다. 예시 파일의 음수 잔여시간을 새 앱의 정상 결과로 취급하지 않는다.
