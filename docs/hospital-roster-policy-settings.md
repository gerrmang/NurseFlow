# 병원·병동 근무 정책 설정 명세

상태: **2026-11-04 요구사항 명세, 정책 설정 API·화면 미구현**. [breakdown 전 제품 결정](pre-breakdown-scope-2026-11-04.md)을 우선한다. 병동 관리자 설정 화면·DB·API·자동편성에 연결하기 위한 입력 목록이다. 외부 병원 검색 결과의 이름·식별자는 병동 표시·연결 정보이며 별도 병원 관리자 권한을 만들지 않는다. 이 문서만으로 정책이 앱에서 동작하지 않는다.

상세 편성 기준은 [월간 근무표 규칙](monthly-roster-rules-and-two-person-plan.md), 제품 범위는 [MVP 범위](mvp-scope.md)를 따른다. 충돌 시 사용자가 앞서 명시적으로 확정한 기준을 유지한다.

## 관리자 설정 화면

입력은 `병동 기본 정책 → 월별 수요·대상자 → 생성 전 검토` 순서로 구성한다. 설정 화면은 저장 전 검증 결과와 변경 영향을 보여주고, 저장 시 정책 버전을 올린다. 근무표 생성 작업은 시작 시점의 정책 버전과 대상자·수요 revision을 함께 고정한다. 이미 생성된 초안은 정책 변경만으로 조용히 바꾸지 않고 재검증 대상으로 표시한다.

| 설정 묶음 | 입력 필드 | 입력/검증 규칙 |
| --- | --- | --- |
| 편성 대상 | 활성 초대 수락 간호사, 이번 달 포함 여부, 편성 제외 여부·관리자 계정 여부 | 활성·수락·해당 병동 소속 간호사만 대상. 관리자 제외는 서버에서 강제하고 화면 선택으로 해제할 수 없다. |
| 팀 | 팀 개수, 팀 이름, 간호사별 소속 팀, 팀별 날짜·근무별 필요 인원 | 팀 수와 이름은 병동별 설정. 0 이상 정수, 대상 간호사의 유효한 소속 여부 확인. |
| 근무 유형 | 코드, 표시 이름, 종류(DAY/EVENING/NIGHT/기타), 시작·종료 시각, 자정 통과, 휴게 분, 실제 인정 시간, 월 목표 환산 시간 | 시간대 겹침·종료 시각·휴게 범위를 검사한다. 실제 근무시간과 목표 환산시간은 별도 보관한다. 지원되지 않는 코드의 뜻은 관리자가 정의하기 전까지 추정하지 않는다. |
| 특수 근무 코드 | 병동 정의 코드(예: 교육·파견·상근), 표시 이름, 적용 대상, 가능 날짜, 실제/환산 시간, 근무일·휴식일 계산 방식 | 병동 관리자가 명시적으로 등록한 코드만 허용한다. `DD`, `DE`, `ET`, `DK`, `DN`, `T2`, `CC`, `VR`, `VX` 등 엑셀 코드를 자동 매핑하지 않는다. |
| 휴가·반차 코드 | 승인 일정 종류, 적용 시작·종료 시각, 오전/오후/사용자 지정 시간 구간, 근무 가능 여부, 목표시간 환산값 | 승인 일정은 관리자가 입력한다. 해당 시간과 실제 근무가 겹치면 불가. 시간대와 환산값은 해당 병동 정책. 사유·건강 정보는 수집하지 않는다. |
| 경력·선임 | 입사 연월→1~5 기본 단계 기준, 관리자 조정 단계·팀 내 순서·선임 자격, 팀·근무별 최소 선임 수 | 간호사는 입사 연월만 제출한다. 관리자는 확인·조정하며 이력을 남긴다. **각 팀의 각 D/E/N에 선임 자격자 1명**이 필수이고 부족하면 선임 미충원으로 표시한다. |
| 근무 자격 | 간호사별 일반 3교대/Day·Evening 전담/Night 전담, 허용 근무 유형 | 비허용 유형은 후보·수동·자동·확정 모든 경로에서 서버가 금지한다. 건강 사유는 저장하지 않는다. |
| Night 전담 | 전담 인원 수, 순환 주기(월), 전담 조 유지 기간, 월 최소 Night 수, 전담 월 목표시간, Night 환산시간, 별도 휴식 정책 | 사용자 결정 기본안은 2명씩 3개월 블록 순환·월 Night 최소 15회. 설정 변경은 명시적 병동 정책 버전으로 관리한다. |
| SOF | 일반 직원 Night 임계 횟수, 부여 일수, Night 전담 별도 규칙, SOF 환산시간 | 사용자 결정 기본안은 일반 직원 월 Night 6회 이상이면 같은 달 자유 날짜에 1일. Night 전담은 별도 정책. 해당 기준은 기본 시연값으로 병동별 변경 가능. 이월은 현재 확정 범위에 포함하지 않는다. |
| 연속·교대 휴식 | 최대 연속 근무일, 연속 Night 상한(2 또는 3 등), 교대 간 최소 휴식 시간, 패턴별 금지 여부 | 사용자 결정 기본안은 최대 5일 연속 근무, 6일째 `OF`/`SOF`. E→다음 날 D는 현재 서버에서 금지한다. 추가 연속 Night/N-E 제한은 병원에서 값을 확정하고 활성화하기 전까지 법적·보편 규칙으로 단정하지 않는다. 활성화 후에는 서버 hard rule로 모든 편성 경로에 동일 적용한다. |
| 희망 오프·주말 휴무 | 개인 월 최대 희망 오프 수, 주말(토/일) 최소 희망 휴무 횟수, 신청 마감, 제출/확정/반려 상태 | 희망 오프는 공식 승인 휴가와 분리한다. 미확정 날짜는 선호로 최적화하고, 관리자 확정 뒤 해당 간호사의 배치를 금지한다. |
| 휴일·월 목표 | 시간대, 주말·공휴일 달력, 대체휴일·병동 예외, 기준 일일 시간, 일반/전담 개인 목표시간 | 목표 환산시간은 병원 달력 정책으로 계산한다. 실제시간·환산시간·목표·잔여·초과를 분리 표시한다. Night의 월 귀속 규칙도 명시한다. |
| 목표 미달 허용 | 대상 근무 유형/직원 분류, 최대 미달 시간(음수 허용 오차) | 일반 직원의 목표시간 음수 잔여를 허용하지 않는 것이 현재 합의안이다. D/E 전담 등 목표가 수학적으로 불가능한 분류에 음수 허용을 두려면 별도 정책으로 대상·최대 미달량·확정 시 경고/차단 기준을 설정한다. 음수 허용을 전체 간호사에 적용하지 않는다. |
| 주간 근무시간 상한 | 산정 주 시작일, 주 최대 실제 근무시간, 예외 대상·정책 버전 | 첨부안의 52시간은 법령 적합성을 확인하지 않은 채 코드에 상수로 넣지 않는다. 국가·기관·직원 유형에 적용되는 한도와 산정 방법을 적법하게 확인한 뒤 활성화한다. |

### 근무 코드 정의와 직원 분류

새 코드의 필수 입력은 `코드`, `표시명`, `분류(실근무/전일 휴식/승인 부재/부분 부재)`, `적용 가능 직원·팀`, `실제 시간 구간`, `휴게시간`, `월 목표 환산시간`, `연속근무 계산 방식`, `팀별 필요 인원·선임 충족에 포함할지`, `정책 유효기간·버전`이다. 실근무는 실제 시작·종료 구간을 가져야 하고, 부재·휴식은 실제 근무시간으로 합산하지 않는다. 반차는 **배치 불가 시간 구간**과 **환산시간**을 별도로 갖는다. 출근/휴무 이분법이나 환산시간 하나만으로 근무 겹침·휴식·충원을 판정하지 않는다. 관리자 정의가 없는 코드는 가져오기·자동생성·수동 배치에서 사용 불가 사유를 표시한다.

엑셀의 `DD`, `DE`, `ET`, `DK`, `DN`, `T2`, `CC`, `VR`, `VX`, `V9`, `VV`, `VS`, `VE`는 **해석 전 코드 후보**다. 코드가 교육·대체·상근·반차를 뜻한다거나 모두 8시간이라는 첨부 설명은 해당 병동 관리자 확인 전에는 확정하지 않는다. D/E 7.5시간, N 9시간, VY/SOF 8시간도 기존 예시처럼 시연 설정 후보이며 코드 상수가 아니다.

직원의 `근무 형태(3교대/Day·Evening 전담/Night 전담/별도 고정근무)`와 `병동 관리자 확인 경력 단계(1~5)`는 분리한다. `계장`, `대체`, `A(5)`, 숫자 태그 등은 해당 병동의 원본 표기 또는 관리자 정의 역할 태그로 저장할 수 있지만, 자동으로 경력 단계·선임 자격·5일 연속근무 면제에 연결하지 않는다. 고정근무자의 편성 대상 포함 여부와 연속근무 정책은 관리자 확인 후 별도 정책으로 지정하고, 휴가·시간 겹침 같은 공통 필수 규칙은 유지한다. 개인의 건강·임신 사유는 입력받지 않는다.

## 자동 편성 엔진 적용 방식

### 필수 제약

- 외부 승인 뒤 등록된 부재·관리자가 확정한 희망 오프와 근무의 겹침, 같은 시간대 중복, Night·Evening 다음날 Day 금지.
- 간호사별 허용 근무 유형, 관리자 계정 제외, 명시적 팀 간 지원 허용 범위.
- 사용자가 확정한 최대 연속 근무 5일 및 OF/SOF 휴식 규칙.
- 각 팀의 각 Day/Evening/Night에 관리자가 확인한 선임 자격자 최소 1명.
- 활성화된 병동별 시간/교대 휴식 제한과 확인된 주간 근무시간 상한.

희망 오프는 **제출만으로 고정되지 않는다**. 미확정 날짜는 가능한 한 반영하는 소프트 목표이고, 관리자가 확정하면 해당 날짜에 그 간호사의 근무를 배치할 수 없다. 공식 VY·반차는 앱 밖의 승인 이후 관리자가 등록한다. 첨부 문구의 VY가 연속근무를 초기화한다는 안은 채택하지 않는다. 기존 결정대로 `OF`·`SOF`만 연속근무를 끊고, `VY`는 근무일도 휴식 리셋일도 아닌 별도 상태다.

### 소프트 목표와 충돌 진단

- 미확정 희망 오프, 주말 휴무, 근무 횟수·시간 균형, 팀·근무별 확인된 1~5단계 분산은 점수화 목표로 둔다.
- 정해진 팀별 인원, 월 목표시간, Night 전담 최소 횟수처럼 필수인지 선택인지 병동 정책이 결정해야 하는 목표는 정책에 성격을 명시한다. 필수로 선택된 경우 불가능하면 자동으로 풀지 않고 생성 불가/미충원 사유를 반환한다.
- 자동 편성은 위반 점수만 최소화하는 방식으로 hard rule을 완화하지 않는다. 불가능한 조합은 누락 규칙 이름, 대상 날짜·근무·팀, 부족 인원/시간을 관리자에게 보여준다.
- 후보 안내, 수동 저장, 자동 생성, 확정이 동일한 서버 정책 버전으로 재검증한다. 간호사 공개 달력은 관리자가 확정하기 전까지 변경하지 않는다.

## 첨부 내용과 기존 합의의 조정

| 첨부 제안 | 적용 결정 |
| --- | --- |
| 팀, 근무시간·휴게, 근무별 필요 인원, 특수 코드, 반차 환산 설정 | 관리자 설정 필드 목록에 추가. 실제 설정 API/UI는 아직 미구현. |
| 개인별 최대 희망 오프와 최소 주말 휴무 | 병동별 설정으로 추가. 희망 오프는 미확정이면 선호, 관리자가 확정하면 배치 금지다. |
| Night 연속 상한, E-D 금지, N-E 최소 휴식 | E→다음 날 D 금지는 별도 구현 PR로 서버 규칙에 추가됐다. Night 연속 상한과 N-E 최소 휴식은 병원에서 값·적용 여부를 결정하는 정책 필드로 둔다. |
| 주 52시간 hard limit | 운영 법령·산정법 확인 전에는 활성화하지 않음. 확인된 상한만 설정 가능한 정책으로 둠. |
| VY를 연속근무 reset으로 계산 | 기존 결정과 상충하므로 미적용. OF·SOF만 reset. |
| 희망 오프를 제출 즉시 1순위로 고정 | 미적용. 관리자가 확정한 날짜만 배치 금지이며 미확정 신청은 best-effort. |
| 일반 목표시간 음수 금지와 D/E 전담 예외 | 일반 직원 기준은 유지. D/E 전담의 최대 허용 미달은 별도 설정을 두되 병원 승인 전까지 기본 예외값은 미정. |
| SOF 이월 | 같은 달 자유 날짜에 배치한다는 기존 결정 유지. 이월 설정은 초기 MVP에 넣지 않음. |
| 잔여 근무시간의 월간 이월 | 현재 합의된 `월간 환산시간 - 개인별 월 목표시간` 표시와 별개 제안이다. 이월을 허용하면 확정본 수정·퇴사·전담 전환 시 정산 기준과 잔여 부호/상한을 먼저 정의해야 한다. 초기 MVP의 자동 목표 조정에는 적용하지 않는다. |
| 연차 부여·사용·잔여 원장 | 기존 MVP에서 법정 연차 계산과 휴가 승인·결재를 제외했다. `VY`/반차는 관리자가 이미 승인된 일정만 입력한다. 자동 차감 원장은 급여·근태 영역과 데이터 정합성 책임을 검토한 뒤 별도 기능으로 결정한다. |
| 상근·대체·Charge 등 별도 태그 | 근무 형태와 경력 단계/선임 자격을 구분해 관리자 확인 항목으로 추가한다. 태그 문자열만으로 5일 연속근무 예외나 Charge 자격을 부여하지 않는다. |
| 필요 인원·선임 조건을 모두 충족해야만 생성 성공 | 필수 선임 부족은 선임 미충원으로 진단한다. 기존 결정대로 미충원 표도 관리자가 수량을 확인한 뒤 공개할 수 있다. |

## 미구현 경계 및 다음 단계

현재 `dev`에는 팀과 경력 프로필 API가 있지만 근무 정책 설정 화면/API는 없다. 휴게·환산시간, 선임 자격의 팀별 필수 배치, SOF·목표시간·휴일 달력·희망 오프 상태·설정 가능한 연속근무/주간 상한은 저장·검증되지 않는다. 서버 validator는 승인 부재 겹침, 동시간 중복, Night·Evening 다음날 Day를 판정한다. 따라서 이 문서의 **신규 코드·희망 오프 상태·관리자 경력 조정·이월 제안**은 아직 실행 정책으로 적용 완료되지 않았다.

구현 순서는 설정 읽기/쓰기 DTO와 병동 정책 revision 계약 → 관리자 설정 화면 → 저장/권한/유효성 검사 → validator 공통 입력화 → 각 규칙 단위 테스트 → 자동 생성 최적화 순으로 기능별 PR로 나눈다. 첫 기능 PR은 설정 묶음 전체를 한 번에 구현하지 않고 `근무 유형·시각·휴게·환산시간`처럼 하나의 검증 가능한 범위만 다룬다. API 경로·요청/응답 스키마는 구현 PR에서 `docs/openapi.yaml`에 추가한다.
