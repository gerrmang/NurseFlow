# NurseFlow 초기 시연 MVP 범위

상태: **2026-11-05 사용자 흐름 보완**. 이 문서는 초기 MVP의 제품 범위를 정한다. [breakdown 전 결정·미결정 사항](pre-breakdown-scope-2026-11-04.md)에 최신 사용자 지시와 기존 문서의 차이를, [월간 편성 규칙과 2인 분담](monthly-roster-rules-and-two-person-plan.md)에 상세 정책을 기록한다. 실제 병원 도입용 정책·보안 적합성을 승인한 문서는 아니다.

## 목표와 시연 조건

- 실제 병원 검색 API를 연결하되 개발·시연의 병동·간호사와 근무표는 가상 데이터로 월간 3교대 근무표를 작성한다. 병원 검색 결과 선택을 재직 인증으로 표시하지 않는다.
- 최초 스케줄 관리자가 Kakao 로그인 뒤 **실제 병원 검색 결과를 선택**하고 병동명을 입력해 자기 병동을 만들며 `WARD_ADMIN`이 된다. 별도 병원 관리자 역할은 두지 않으며, 간호사는 해당 병동의 초대로만 참여한다. 병원 선택은 재직 인증이 아니다.
- 관리자가 사전에 취합한 **확정된 휴가·반차 일정**을 시간 구간으로 등록한다. 사유·진단 정보는 받지 않는다.
- 자동 배치는 필수 규칙을 지킨 초안만 만든다. 관리자가 가능/불가 사유, 미충원, 균등 배분을 보고 수동 수정한 뒤 확정·공개한다.
- 병동 안의 소속 팀별로 편성하고, 같은 날짜·근무(Day/Evening/Night)·팀의 인원이 경력 단계 1~5에 가능한 한 고르게 분포하도록 한다. 인원과 가용성 때문에 불가능하면 경력 구성 미달 이유를 관리자에게 보여준다.
- 초대를 수락한 활성 간호사 수를 D/E/N 편성 모수로 삼는다. 스케줄 관리자의 본인 일정은 앱 근무표에 입력·표시하지 않고 자동배치·충원 계산에서도 제외한다. 팀 개수, 3교대 시각, SOF 기준, 월 목표시간과 Night 전담 순환은 병원·병동 정책으로 설정한다.
- 간호사의 희망 오프를 승인된 연차·반차와 별도로 취합한다. 제출 상태에서는 가능한 한 반영하고, 관리자가 확정한 날짜는 해당 간호사의 근무 배치를 금지한다. 연속근무 상한과 개인별 월 목표시간을 함께 검증한다.
- 관리자 정책 설정에는 팀·대상자, D/E/N 및 특수 근무 시간·휴게·환산값, 반차 구간, 근무 자격, Night/SOF, 연속·교대 휴식, 희망 오프/주말 목표, 휴일 달력·월 목표, 확인된 주간 상한을 병원별로 관리한다. 목표시간 미달은 별도 진단·명시 확인으로 공개 여부를 처리한다. 필드별 우선순위·현재 미구현 경계는 [정책 설정 명세](hospital-roster-policy-settings.md)를 따른다.
- Android 앱과 반응형 웹에서 **같은 Spring Boot API와 공개 revision**을 사용한다. 관리자와 간호사의 핵심 흐름을 두 클라이언트에서 모두 제공한다.
- 초기 시연에는 실사용 병원 직원 정보를 넣지 않는다. 엑셀 대비 작성시간 50% 이하 목표는 실제 파일럿에서 기준 시간을 측정한 뒤 평가한다.

| 시간대 | 시연 병동은 Asia/Seoul. Night가 월 경계를 넘는 경우에도 전·다음 달 공개 근무를 검증한다. |

## 계정과 권한

| 상태/역할 | 허용 작업 |
| --- | --- |
| Kakao 로그인만 완료 | 본인 세션 확인, 새 병동 생성 또는 유효한 초대 수락. 기존 타 병동 데이터 조회 불가 |
| 병동 간호사 (`WARD_MEMBER`) | 가입 과정에서 해당 병원 입사 연월 입력·수정, 희망 오프 제출, 자신이 속한 병동의 **확정·공개된** 전체 근무표와 본인 근무표 조회. 초안·관리자용 부재 목록 조회 불가 |
| 병동 관리자 (`WARD_ADMIN`) | 자기 병동의 초대 생성·철회, 구성원/권한·팀 소속 관리, 실제 경력 시작 연월·직급 입력, 팀별 경력순 조정·선임 자격 지정, 팀 간 지원근무 허용, 근무 유형·팀별 필요 인원·확정된 불가 일정·희망 오프 대리 입력/확정/반려, 자동·수동 배치, 초안 검토, 확정·공개 |

관리자의 `WARD_ADMIN` 권한은 일정 편집·확정 권한이다. 관리자 본인 일정은 이 앱의 근무표에 포함하지 않으며 팀별 선임·충원 인원으로도 세지 않는다.

- 초대는 병동, 초대할 역할, 필요하면 연결할 가상 간호사 기록을 지정한다. 유효기간은 **24시간 고정**이며 1회 사용·철회를 지원한다. 링크를 발급·복사·공유할 수 있고 만료되면 새로 발급한다. 서버에는 토큰 원문 대신 해시를 저장한다.
- Kakao 인증을 마친 사용자가 초대를 수락하면 사용자·병동 소속과 해당 간호사 연결을 **한 트랜잭션에서** 생성하거나 기존 가상 기록에 연결한다. 같은 초대나 동일 간호사 연결의 중복을 거부한다. 사용자가 자기 역할을 선택하거나 승격할 수 없다.
- 최초 관리자는 **자기가 생성한 새 병동에 한해서만** `WARD_ADMIN`이 된다. 병동 생성은 기존 병동에 가입하거나 타 병동 권한을 얻는 수단이 아니다. 현재 코드의 초기 설정 코드 방식은 이 새 흐름으로 교체해야 한다.
- 권한은 로그인 토큰의 주장만 믿지 않고 서버의 병동 소속 기록으로 다시 확인한다. 권한 변경, 초대 수락, 경력 프로필 확인과 단계 기준 변경은 감사 기록을 남긴다.
- 초대받은 간호사는 **해당 병원 입사 연월만** 입력한다. 실제 경력 시작 연월과 직급은 관리자가 따로 설정한다. 팀 배정 뒤 관리자가 팀 안의 경력순을 드래그해 조정하며, 위에 놓인 순서가 경력 순위를 결정한다. 입사 연월과 수동 순서가 다르면 수동 순서를 따른다. 간호사는 직급명·팀·경력순·선임 자격을 스스로 지정하지 않는다.

### 첫 사용과 초대 경험

- 첫 병동 생성에서는 병원 검색 결과와 병동명만 입력한다. 생성 뒤 설정 안내 화면에서 팀·대상자·D/E/N 시각·환산시간·팀별 수요·선임·휴식 정책을 단계별로 확인한다. 첫 초안 생성에 필요한 항목이 빠지면 구체적인 누락 항목을 보여준다. 제시한 기본값은 병원의 실제 운영 정책으로 자동 승인된 값이 아니다.
- 관리자는 초대 대상별 발급·사용·만료·철회 상태와 미가입자를 확인하고 개별 재발급한다. 초대 링크는 1회용이므로 여러 간호사가 공유해 가입하는 방식으로 안내하지 않는다.
- 병원 검색 결과가 없거나 외부 서비스가 응답하지 않는 경우를 구분해 표시하고 재시도·관리자 문의 경로를 제공한다. 검색되지 않는 기관의 수동 등록 가능 여부는 별도 결정한다.

## 근무 불가 정보와 편성 규칙

1. 관리자가 병원 밖에서 이미 승인된 VY와 오전/오후 반차 시간 구간을 등록한다. 이번 MVP는 공식 휴가 결재를 처리하지 않는다. 간호사의 별도 희망 오프는 제출만으로 근무 금지가 되지 않고, 관리자 확정 뒤에만 고정된다.
2. 배치 후보 조회, 수동 저장, 자동 생성, 최종 확정은 모두 서버의 같은 필수 규칙 검증을 거친다. 클라이언트의 초록/빨강 표시는 안내이며 최종 판정은 서버가 한다.
3. 등록된 근무 불가 구간과 실제 근무 시간이 겹치면 배치하지 않는다. 예를 들어 오후 반차 시간과 Evening 근무가 겹치면 후보에서 불가 사유를 보여준다.
4. 같은 간호사의 근무 시간 중복과 **Night·Evening 다음날 Day** 배치를 금지한다. Night 23:00–다음 날 07:00의 날짜 해석과 월 경계를 함께 처리한다. Night 이력은 간호사가 직접 입력하는 불가 일정이 아니라 실제 근무표에서 계산한다.
5. 관리자가 날짜·근무 유형별 필요 인원과 자격 조건을 입력한다. 부족한 경우 규칙을 완화하지 않고 슬롯을 비워 두며 인원과 사유를 보여준다.
6. 균등 배분은 필수 규칙과 충원 다음의 목표다. 시연 MVP에서는 총 근무 수와 Night 횟수의 편차를 보고한다. 최적성이 입증되지 않은 결과를 ‘최적’으로 표시하지 않는다.
7. 자동 생성은 비공개 초안만 변경한다. 이미 공개된 표는 관리자가 새 초안을 검토·확정할 때까지 유지된다. 미충원이나 개인별 월 목표시간 미달이 남으면 각각의 대상·규모·사유를 보여주고 관리자의 명시적 확인을 받은 뒤 공개할 수 있다. 확인 기록을 revision과 연결한다. 필수 배치 규칙 위반은 확인으로 면제되지 않는다.
8. 팀별 경력 단계 조합은 **최대한 맞추는 편성 목표**다. 한 근무 칸 수가 5명보다 적거나 해당 팀의 특정 단계 인원이 휴가·반차·휴식 규칙으로 불가하면 1~5단계를 모두 채우도록 강제하지 않는다. 필수 규칙을 지키고 필요한 인원을 최대한 채운 뒤 확인된 경력 단계의 쏠림을 줄인다. 미확인 프로필은 경력 구성 점수에 넣지 않고 관리자에게 별도 표시한다. 목표를 못 맞춘 경우 `미충원`과 구분해 경력 구성 미달 사유와 실제 단계 분포를 관리자에게 표시한다. 경력 단계만을 이유로 합법적인 배치를 금지하거나 자동 확정을 해서는 안 된다.
9. 간호사는 원칙적으로 소속 팀 근무에 배치한다. 다른 팀의 근무에는 **병동 관리자가 명시적으로 허용한 범위에서만** 지원 배치할 수 있다. 허용 범위에는 대상 간호사·배치 팀·적용 근무 또는 기간을 구분한다. 허용 기록이 없거나 유효 범위 밖이면 후보 안내, 수동 저장, 자동 생성, 최종 확정에서 서버가 배치를 거부하고 사유를 표시한다. 허용된 지원근무는 원 소속 팀이 아니라 **실제 배치 팀**의 필요 인원과 경력 단계 분포에 포함한다. 팀 간 지원을 이유로 휴가·반차·Night 휴식·중복 근무 규칙을 완화하지 않는다.
10. 병원별 Day/Evening/Night 실제 시각과 월간 환산시간을 분리해 설정한다. 주말·공휴일을 중복 없이 반영한 목표일수와 기준 1일 시간으로 월 목표시간을 계산하고, 초안에서 개인별 실제·환산·목표·잔여시간을 보여준다. 목표시간 미달은 해결을 우선하되, 남은 경우 관리자에게 개인별 부족 시간·사유를 명시적으로 확인받아 공개할 수 있다. Night 전담은 별도의 목표·Night 환산시간·휴식 정책을 사용하고 VY/SOF의 환산시간도 병원별로 설정한다.
11. 간호사별 일반 3교대·Day/Evening 전담·Night 전담 근무 형태를 설정한다. Night 전담은 기본 2명이 연속 3개월 근무한 뒤 다른 2명과 교대하며 각 전담자의 월 Night는 최소 15회다. 일반 간호사는 월 Night 6회 이상이면 **같은 달의 자유로운 날짜에** SOF 1일을 부여하고 Night 전담은 별도 정책을 적용한다. 연속근무는 최대 5일로 월 경계를 넘어 검증하며 `OF`·`SOF`만 연속근무를 끊고 `VY`는 근무일도 휴식 리셋일도 아닌 별도 상태로 처리한다. 병원별 숫자는 정책으로 변경할 수 있다.
12. 희망 오프는 간호사가 직접 제출하거나 관리자가 대신 입력하며 입력 주체를 기록한다. 관리자는 제출된 희망 오프를 확정·반려할 수 있다. 월별 제출 마감 전에는 간호사가 변경할 수 있고, 마감 뒤에는 관리자가 예외 요청을 접수·확정한 뒤 영향받는 초안을 재검증한다. 제출 후 미확정 날짜는 가능한 한 반영하는 선호 목표이고 미반영 사유를 보여준다. 확정된 날짜는 해당 간호사의 근무 배치 금지다. 병동이 정한 선임 자격자 **각 팀·각 Day/Evening/Night 최소 1명**은 필수 조건이며 충족할 수 없으면 해당 필요 칸을 미충원으로 표시한다.

## 시연 화면과 공통 흐름

1. 소속 전: Kakao 로그인 → 실제 병원 검색·선택과 병동명 입력으로 새 병동 만들기(최초 관리자) 또는 초대 수락(간호사·추가 관리자).
2. 초대 수락: 링크 열기 → Kakao 로그인(필요 시) → 병동/역할 확인 → 소속 생성 → 병동 선택.
3. 관리자: 팀·간호사 경력 프로필 확인 → 근무 유형·팀별 필요 인원 입력 → 사전 취합된 근무 불가 구간 등록 → 자동 배치 또는 수동 배치 → 가능/불가 사유, 미충원과 경력 단계 분포 검토 → 수정 → 확정·공개.
4. 간호사: 공개된 병동 전체/내 근무 전환 → 날짜별 근무자 확인. 비공개 사유·초안은 보이지 않는다.
5. Android와 웹은 같은 병동·월·revision을 표시한다. 한쪽에서 확정한 뒤 다른 쪽이 새로 조회하면 같은 공개본이 나온다.
6. 첫 공개 전 간호사 달력은 대상 월과 ‘아직 확정된 근무표가 없습니다’를 표시한다. 초안의 존재·배치 내용·비공개 사유는 노출하지 않는다.
7. 공개 후 승인된 VY·반차, 직원 비활성화 또는 정책 변경이 생기면 현재 공개본을 유지하면서 수정 초안을 만들고 영향받는 날짜·인원·시간을 표시한다. 관리자 재검증·재확정 성공 시 새 revision으로 공개본을 교체한다. Android·웹에 변경 표시와 이전/현재 근무 비교를 제공한다. 초기 버전에는 푸시 알림을 넣지 않는다.

## 시연 인수 기준

1. 초대받지 않은 Kakao 계정은 **기존** 병동 근무표와 개인정보를 조회할 수 없다. 자기 새 병동 생성만 허용한다. 초대는 24시간 만료·재사용·다른 병동 사용이 차단된다.
2. 초대 수락 후 사용자·병동 소속·간호사 연결이 중복 없이 생성되고, 역할 변경은 관리자만 가능하다.
3. 관리자가 근무 유형·필요 인원·확정된 불가 구간을 입력한 뒤 월간 초안을 생성할 수 있다.
4. 휴가/반차 시간 중복, 같은 간호사 근무 중복, 전날 Night·Evening→다음날 Day는 **후보 안내뿐 아니라 서버의 모든 저장·생성·확정 경로에서 0건**이다. 월 경계도 포함한다.
5. 채울 수 없는 칸은 미충원 수와 이유가 보이고, 자동 생성이 필수 규칙을 임의로 어기지 않는다.
6. 관리자 확정 전 초안은 간호사 API·Android·웹에서 보이지 않는다. 미충원과 월 목표시간 미달은 각각 대상·규모·사유를 관리자에게 보여주고 명시 확인한 경우에만 공개할 수 있다. 필수 배치 규칙 위반은 계속 차단한다.
7. 확정 후 Android와 웹에서 병동 전체와 본인 보기가 동일한 활성 revision을 읽는다. 다른 병동 사용자는 접근할 수 없다.
8. 두 관리자의 동시 편집과 중복 실행은 revision·멱등성 검사로 안전하게 처리된다.
9. 가상 데이터의 **완전 충원 가능 사례와 미충원 사례**를 각각 시연한다. 실제 병원 생산성 50% 개선은 시연 성공 주장에 포함하지 않는다.
10. 가상 병동의 A/B팀과 경력 단계 1~5를 준비한다. 동일 팀·날짜·근무에서 가능한 단계 분산을 개선한 사례와, 휴가·인원 부족 때문에 목표를 못 맞추되 필수 규칙은 지킨 사례를 재현하고 관리자에게 구성 미달 사유를 보여준다.
11. A팀 간호사의 B팀 근무는 관리자 허용이 없을 때 자동·수동·확정 경로에서 거부된다. 허용 범위 안에서는 B팀 충원과 경력 구성에만 반영되며, 허용 철회·범위 밖 배치·동시간 중복은 다시 거부된다.
12. 초대를 수락한 활성 간호사만 D/E/N 자동편성에 참여하고 관리자 본인 일정은 근무표·충원 계산·공개표에 포함되지 않는다. 병원별 근무 시각·시간 환산 및 근무 형태가 다른 간호사를 가상 데이터로 시연한다.
13. 월 목표시간 168시간 예시(30일 중 기준 휴식일 9일, 하루 8시간)를 재현한다. 목표시간 미달, 초과, Night 전담 정책 충돌을 구분해 표시하고 필수 규칙을 깨서 시간을 채우지 않는다.

## 이번 MVP에서 제외

- 간호사 본인의 공식 휴가·반차 신청/결재 또는 근무 불가 직접 등록, 희망 오프 외 근무 유형 선호 입력
- 급여·근태·출퇴근, 법정 연차 계산, 환자 정보·진단·휴가 사유 수집
- 생성형 AI가 필수 규칙을 판단하거나 자동 확정·공개하는 기능
- 실제 병원 직원 데이터, 폐쇄망 단일 PC 모드, Cloudflare D1/Workers DB 전환
- 엑셀 가져오기·내보내기, iOS 앱, 통계 그래프, 광고·과금, 제조업 등 타 업종 확장

## 현재 코드와 남은 구현

- `backend/`에는 H2 기반 초안·근무 불가·수동 배치·확정·공개, Kakao ID 토큰 검증·NurseFlow 세션(Android)과 웹 서버 주도 Kakao 로그인, 초대 발급·철회·수락, 팀·경력 프로필 API가 있다. 2026-11-10 기준 공식 병원 목록 복제 검색(A3)과 병원 선택 기반 자기 병동 생성(A4)이 병합됐고 시연용 부트스트랩 코드는 제거됐다. 관리자 지정 팀 안 경력순·선임 자격·편성 단계(A5)는 PR #37에서 검토 중이다. 구성원 관리(A6)·편성 대상 판정(A7), 실제 Kakao 앱 E2E와 운영 DB 이전은 남아 있다. 최신 진행은 [공유 작업 현황](work-status.md)을 기준으로 한다.
- 현재 DB·API에는 팀·경력 프로필의 일부가 있으나 팀 간 지원 허용 기록, 간호사별 근무 형태, 병동별 시간·SOF·휴일·월 목표 정책, 희망 오프, Night 전담 순환, 팀별 경력 구성·시간 진단은 없다. 이 규칙들은 요구사항이며 아직 구현된 기능이 아니다. [상세 규칙](monthly-roster-rules-and-two-person-plan.md)의 미결정 항목을 정하고 각 기능을 별도 PR로 구현한다.
- `android/`의 `dev`에는 Figma 기반 시연 화면과 개발용 토큰으로 확인하는 일부 서버 화면이 있다. 실제 Kakao 로그인·초대·프로필의 최신 `dev` 통합, 확정 근무표의 서버 조회는 아직 끝나지 않았다. 로컬 가상 근무표를 공유 근무표로 표시하지 않는다.
- 웹 클라이언트는 새로 만들어야 한다. Android·웹 모두 인증/초대, 공통 API, 오류·revision 처리를 연결해야 한다.
- [현재 OpenAPI](openapi.yaml)는 Kakao 세션·초대·팀/경력 프로필의 계약을 포함한다. A1은 24시간 초대와 병원 입사 연월 입력, 관리자 실제 경력 입력을 정의한다. 실제 병원 검색·자기 병동 생성·확정 희망 오프·관리자 팀별 수동 경력 순서는 후속 기능 PR에서 추가한다.
